Разработка и применение программного обеспечения в физических исследованиях

Декораторы и модуль functools

Одна и та же обвязка кочует из функции в функцию, будь то замер времени, запись вызова в журнал, проверка аргументов или кеширование результата. Логика везде своя, обвязка одна, а копировать её приходится в каждую. Декораторы позволяют навесить поведение на функцию, не трогая её тело.

Глава о том, как декоратор устроен изнутри, как передать ему аргументы, какие ловушки при этом возникают, и о готовых декораторах из модуля functools.

Синтаксис декораторов

Декоратор — это функция, принимающая другую функцию и возвращающая новую (или любой другой объект). Значок @ перед определением — синтаксический сахар, не добавляющий возможностей, зато выносящий имя декоратора на видное место перед функцией.

@decorator
def foo(x):
    return 42

Эквивалентно:

def foo(x):
    return 42

foo = decorator(foo)

После применения декоратора имя foo ссылается на результат вызова decorator(foo).

Устройство простого декоратора

Разберём устройство на декораторе trace, печатающем каждый вызов функции. Декоратор получает исходную функцию в func и определяет новую, inner; та принимает аргументы в самом общем виде *args, **kwargs, применимом к любой функции; inner делает своё дело, передаёт управление оригиналу и возвращает полученный результат. Наружу декоратор отдаёт inner.

def trace(func):
    def inner(*args, **kwargs):
        print(func.__name__, args, kwargs)
        return func(*args, **kwargs)
    return inner

func остаётся доступной внутри inner даже после завершения trace: это замыкание, разобранное в главе про функции.

Применим его.

@trace
def identity(x):
    "I do nothing useful."
    return x

identity(42)  # Вывод: identity (42,) {} → 42

Проблема атрибутов функции

Побочный эффект: после декорирования имя identity ссылается уже не на исходную функцию, а на inner со всеми её атрибутами. Документация, имя и сигнатура берутся теперь от обёртки, и help ничего полезного не покажет.

identity.__name__  # 'inner'
help(identity)     # Справка о inner, а не identity

Кроме неудобства при отладке, это ломает всё, что опирается на имена функций, от автоматически собираемой документации до фреймворков, ищущих обработчики по имени.

Спасение через functools.wraps

functools.wraps — декоратор, копирующий в обёртку метаданные оригинала (__name__, __doc__, __module__); ссылка на исходную функцию кладётся в __wrapped__. Пишешь свой декоратор — всегда ставь @functools.wraps(func) над внутренней функцией.

import functools

def trace(func):
    @functools.wraps(func)
    def inner(*args, **kwargs):
        print(func.__name__, args, kwargs)
        return func(*args, **kwargs)
    return inner

Теперь identity.__name__ и help(identity) отдают данные оригинала.

Декораторы с аргументами

Иногда декоратор нужно настроить, скажем указать trace, куда писать. Тут появляется третий уровень вложенности. Запись @trace(sys.stderr) означает два действия: сначала вызывается trace(sys.stderr), и только полученный результат применяется к функции как декоратор, а значит, trace возвращает декоратор, который уже возвращает обёртку.

import sys


def trace(handle):
    def decorator(func):
        @functools.wraps(func)
        def inner(*args, **kwargs):
            print(func.__name__, args, kwargs, file=handle)
            return func(*args, **kwargs)
        return inner
    return decorator

@trace(sys.stderr)
def identity(x):
    return x

Эквивалентно:

decorator = trace(sys.stderr)
identity = decorator(identity)

Декораторы с опциональными аргументами

Два декоратора, написанных выше, несовместимы по способу применения: один пишется как @trace, другой только как @trace(...). Чтобы работали оба, декоратор смотрит на переданное ему значение. Пришла func — его применили без скобок и надо сразу возвращать обёртку. Пришло пусто — вызов сделан со скобками, и вернуть надо декоратор, применяемый следующим шагом.

def trace(func=None, *, handle=sys.stdout):
    if func is None:
        return lambda func: trace(func, handle=handle)

    @functools.wraps(func)
    def inner(*args, **kwargs):
        print(func.__name__, args, kwargs, file=handle)
        return func(*args, **kwargs)
    return inner

Использование:

@trace
def foo(): ...

@trace(handle=sys.stderr)
def bar(): ...

Без звёздочки в объявлении @trace(sys.stderr) попало бы в func, и декоратор принял бы файловый объект за декорируемую функцию. Требование передавать настройки только по имени убирает неоднозначность.

Полезные декораторы на практике

Декоратор @timethis для замера времени

Декоратор для замера времени выполняет функцию n_iter раз и печатает лучший результат, а не средний. Среднее портит любая случайная помеха вроде переключения задач операционной системой, а минимум показывает, на что код способен в спокойной обстановке. По той же причине в стандартной библиотеке есть timeit.repeat, возвращающий список замеров, из которого берут min. Сам timeit.timeit минимума не считает и отдаёт суммарное время всех запусков, делить которое на их число приходится самому.

import time

def timethis(func=None, *, n_iter=100):
    if func is None:
        return lambda func: timethis(func, n_iter=n_iter)

    @functools.wraps(func)
    def inner(*args, **kwargs):
        print(func.__name__, end=" ... ")
        acc = float("inf")
        for i in range(n_iter):
            tick = time.perf_counter()
            result = func(*args, **kwargs)
            acc = min(acc, time.perf_counter() - tick)
        print(acc)
        return result
    return inner

Декоратор @once для однократного вызова

Бывает работа, которую делают один раз, сколько бы раз функцию ни звали: чтение конфигурации, установка соединения, разбор большого справочника. @once запоминает результат первого вызова и дальше отдаёт сохранённое значение.

Хранить состояние декоратор мог бы в замыкании, но здесь оно положено на inner: функция тоже объект и допускает произвольные атрибуты. Флаг при этом виден снаружи, и some_func.called покажет, звали функцию или нет.

def once(func):
    @functools.wraps(func)
    def inner(*args, **kwargs):
        if not inner.called:
            inner.result = func(*args, **kwargs)
            inner.called = True
        return inner.result
    inner.called = False
    return inner

Декоратор @memoized и мемоизация

Мемоизация — запоминание результата отдельно для каждого набора аргументов. Функция ведёт словарь «аргументы → результат» и ничего не считает повторно, если ответ уже сохранён. Ключом служит кортеж из позиционных аргументов и отсортированных именованных; сортировка нужна, чтобы f(a=1, b=2) и f(b=2, a=1) попали в одну ячейку.

def memoized(func):
    cache = {}
    @functools.wraps(func)
    def inner(*args, **kwargs):
        key = args + tuple(sorted(kwargs.items()))
        if key not in cache:
            cache[key] = func(*args, **kwargs)
        return cache[key]
    return inner

Ключом словаря может быть только хешируемый объект, поэтому такая мемоизация сломается, если в функцию передать список, словарь или множество. Ради универсальности аргументы сериализуют, например через pickle, но тогда теряется скорость. На практике проще применять мемоизацию только к функциям с простыми аргументами и брать готовый functools.lru_cache, разобранный ниже.

Декоратор @deprecated для устаревших функций

Когда функцию собираются убрать, её сначала помечают устаревшей. Она ещё работает, но при каждом вызове выводит предупреждение в поток ошибок. Это даёт пользователям библиотеки время переписать код.

import warnings

def deprecated(func):
    @functools.wraps(func)
    def inner(*args, **kwargs):
        warnings.warn(
            f"{func.__name__} устарела и будет удалена",
            category=DeprecationWarning,
            stacklevel=2,      # показать строку вызывающего кода, а не эту
        )
        return func(*args, **kwargs)
    return inner

Предупреждение должно выдаваться при вызове функции, поэтому warnings.warn стоит внутри inner. Если вынести его в тело декоратора, предупреждение сработает один раз при импорте модуля и больше никогда: пользователь получит сообщение об устаревшей функции, возможно даже не вызванной им, а при настоящих вызовах не услышит ничего.

Аргумент stacklevel=2 переводит указатель со строки внутри декоратора на ту, где функцию вызвали; без него место вызова по предупреждению не найти.

DeprecationWarning по умолчанию скрыт везде, кроме __main__. Чтобы увидеть его в своём коде, запусти интерпретатор с ключом -W default или добавь строку warnings.simplefilter("always", DeprecationWarning).

Контрактное программирование с декораторами

Контрактное программирование состоит в том, чтобы описывать в самой функции условия, требуемые от входа, и обещания, даваемые на выходе. Проверка, приписанная декоратором рядом с объявлением, видна сразу, а тело функции остаётся чистым. Напишем два, @pre для предусловия и @post для постусловия. Оба принимают проверяющую функцию и текст сообщения: pre проверяет аргументы до вызова, post — результат после.

def pre(cond, message):
    def decorator(func):
        @functools.wraps(func)
        def inner(*args, **kwargs):
            assert cond(*args, **kwargs), message
            return func(*args, **kwargs)
        return inner
    return decorator

def post(cond, message):
    def decorator(func):
        @functools.wraps(func)
        def inner(*args, **kwargs):
            result = func(*args, **kwargs)
            assert cond(result), message
            return result
        return inner
    return decorator

Использование:

import math


@pre(lambda x: 0 < x < 1, "argument must be a fraction")
@post(lambda r: r < 0, "log of a fraction must be negative")
def log_fraction(x):
    return math.log(x)

assert выбрасывается из кода целиком, если интерпретатор запущен с ключом -O. Для контрактов внутри своей программы это подходит: в отладке проверяем, в бою не платим. Данные, пришедшие извне, assert-ом проверять нельзя, там нужен явный raise.

Цепочки декораторов

Декораторов на одной функции может быть несколько, и порядок их важен.

@deco1
@deco2
def foo(): ...

Применяются они снизу вверх, ближайший к def — первым.

foo = deco1(deco2(foo))

При вызове управление идёт в обратную сторону: сначала во внешний deco1, потом во внутренний deco2 и только потом в саму функцию. Поэтому @functools.lru_cache ставят выше проверок, чтобы попадание в кеш не тратило время на валидацию, а @timethis ставят ниже, чтобы он мерил саму функцию, а не работу декораторов, навешенных сверху.

Модуль functools

Мемоизация с ограничением через lru_cache

Готовая замена нашему @memoized. Кеш ограничен по размеру, и при переполнении из него вытесняется запись, к которой дольше всего не обращались, — так расшифровывается LRU, least recently used. Благодаря ограничению кеш не съедает всю память в долго живущей программе.

@functools.lru_cache(maxsize=128)
def expensive_func(x):
    return x * x

Значение maxsize=None снимает ограничение, и так делают только для функций с заведомо небольшим числом различных аргументов. Метод cache_info() покажет число попаданий и промахов. Если попаданий почти нет, кеш только мешает. Ограничение то же, что у самописного варианта: аргументы обязаны быть хешируемыми.

Частичное применение через partial

partial закрепляет часть аргументов и возвращает новую функцию, которой закреплённые аргументы передавать уже не нужно. Это замена лямбде там, где надо донастроить готовую функцию перед передачей дальше.

f = functools.partial(sorted, key=lambda x: x[1])
f([('a', 4), ('b', 2)])  # [('b', 2), ('a', 4)]

Обобщённые функции и singledispatch

Когда функция должна вести себя по-разному для разных типов, напрашивается лестница из isinstance. Она работает, но её приходится править всякий раз, когда появляется новый тип. С singledispatch базовая функция объявляется один раз, а реализации для конкретных типов регистрируются отдельно, в том числе из другого модуля.

@functools.singledispatch
def pack(obj):
    raise TypeError(f"Unsupported type: {type(obj)}")

@pack.register(int)
def _(obj):
    return b"I" + hex(obj).encode("ascii")

@pack.register(list)
def _(obj):
    return b"L" + b",".join(map(pack, obj))

Выбор реализации идёт по типу первого аргумента, отсюда «single» в названии. Зарегистрированные функции названы _, потому что обращаться к ним напрямую не нужно: вызывать всегда будут базовую pack.

Свёртка последовательности через reduce

reduce сворачивает последовательность в одно значение, беря первые два элемента, применяя к ним функцию, а к полученному результату применяя её же со следующим элементом, и так до конца.

functools.reduce(lambda acc, x: acc * x, [1, 2, 3, 4])  # 24

В функциональных языках это базовая конструкция, а в Python её применяют редко: явный цикл читается лучше, а для самых частых свёрток есть готовые sum, min, max и any.

Заключение

Декоратор добавляет функции поведение, не трогая её тело, и тем самым не даёт размазать одну и ту же обвязку по всей программе.

Что понадобится на практике:

  • Свой декоратор всегда начинается с @functools.wraps(func) над внутренней функцией.
  • Декоратор с аргументами — функция, возвращающая декоратор; уровней вложенности становится три.
  • Настройки декоратора делай ключевыми аргументами, иначе @deco и @deco(...) не отличить.
  • В цепочке декораторов ближайший к def применяется первым, а при вызове срабатывает последним.
  • Прежде чем писать своё, загляни в functools: lru_cache, partial, singledispatch и total_ordering закрывают большую часть нужд.
