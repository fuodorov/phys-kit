# Хеш-функции

Массив хорош тем, что даёт мгновенный доступ по номеру, вычисленному заранее. Но искать нередко приходится не по номеру, а по имени, будь то название города, идентификатор события, записанного детектором, или имя файла, сохранённого на диске.

Перебирать всё подряд слишком медленно. Придуманный для данной задачи ответ на редкость элегантен: номер ячейки, отведённой под пару, можно **вычислять** прямо из ключа. Этим и занимаются хеш-функции, на которых построены словари и множества, применяемые тобой каждый день.

В этой главе мы разберём, как ключ превращается в номер корзины, почему разные ключи иногда попадают в одну и ту же корзину и что делать с ключами, столкнувшимися в общей ячейке, а заодно поймём, откуда берётся у словаря та самая сложность \\(O(1)\\), обещанная документацией.

## Что такое отображение
О массивах мы говорили в главе про структуры данных, и сейчас они нам очень пригодятся. Напомним, что в интерфейсе массива, разобранном там, есть две основные операции:

* `get(index: int) -> value` возвращает значение `value` из ячейки с индексом `index`;
* `set(index: int, value: ValueType)` записывает значение `value` в ячейку с индексом `index`.

Каждая из этих операций выполняется за \\(O(1)\\), и это очень быстро! Однако у массивов есть одно серьёзное ограничение, накладываемое устройством памяти: хотя в ячейках можно расположить объекты любого типа, индексы, приписанные этим ячейкам, могут быть исключительно целыми числами.

Но в программе часто возникает необходимость получить объект не по его порядковому номеру, то есть индексу ячейки, занятой объектом, а по другому признаку, отличающему его от соседей, например по названию, или, как говорят программисты, получить значение (англ. value) по ключу (англ. key).

Давай представим, что у нас есть множество городов и множество стран, причём одному городу отвечает единственная страна, названная в справочнике его родиной, и никакой другой быть не может.

```text
   города                страны
   ──────                ──────
   Новосибирск  ──┐
   Москва       ──┼───▶  Россия
   Казань       ──┘
   Минск        ─────▶   Беларусь
   Астана       ─────▶   Казахстан
```

Нужно написать программу-справочник, узнающую по городу страну, где тот расположен. А ещё, если справочник будет пополняться, пригодится функция, добавляющая новую пару «город, страна».

В этой задаче город служит ключом, а страна — значением, и каждому городу отвечает одна-единственная страна, ни больше ни меньше. А вот на страну, занесённую в справочник, может указывать любое количество городов.

Сопоставление, устроенное так, что каждому объекту первого множества (множество городов) отвечает единственный объект второго (множество стран), называется «отображением» (англ. map).

*Отображение служит другим названием математического термина «функция», или «функциональная зависимость». Чаще всего функции отображают числа, отложенные на оси X, в другие числа, отложенные на оси Y. Для каждого числа, взятого из области определения, можно выписать другое число — значение функции в этой точке.*

Массивы тоже представляют собой частный случай отображения, сопоставляющий целому числу любое значение. Например, массив `["яблоко", "груша", "яблоко"]` отдаёт по числам `0` и `2` строку `яблоко`, а по числу `1` строку `груша`, записанную в среднюю ячейку.

Чтобы работать с отображениями, нам требуется похожая на массив структура данных, умеющая получать и сохранять значения:

* `get(key: KeyType) -> value` возвращает значение `value` по ключу `key`;
* `set(key: KeyType, value: ValueType)` записывает значение `value` по ключу `key`.

Но вместо целочисленного индекса она должна допускать ключ произвольного типа, выбранного программистом.

Интерфейс, описывающий две этих операции, называют `Map`, а любую структуру, которая его реализует, называют **«ассоциативным массивом»** (англ. associative array).

### Ассоциативные массивы

В большинстве языков программирования ассоциативные массивы встроены в язык.

Чаще всего их называют так же, как интерфейс, то есть `Map`, «отображение», или используют производные от слова «хеш-таблица»: `Hash`, `HashMap`, `HashTable` и даже просто `Table`. Эти названия подчёркивают способ, выбранный для реализации интерфейса отображения. Встречаются и другие наименования, например в Python ассоциативные массивы называют *«словарями»* (англ. dictionary).

Есть два популярных способа реализовать или, как говорят программисты, имплементировать отображение, живущее в памяти. Первый из них, хеш-таблицы, мы рассмотрим в этой главе, а второй, основанный на деревьях поиска, подождёт до следующей. В некоторых языках встречаются сразу обе реализации, разведённые по разным классам: в Java это `HashMap` и `TreeMap`, а в C++ им соответствуют `std::unordered_map` и `std::map`.

Ассоциативный массив оказался настолько полезной структурой, что во многих языках есть отдельный синтаксис, предусмотренный для его создания. К примеру, в Python отображение реализовано типом `dict`, вшитым прямо в интерпретатор.

### Наивная реализация ассоциативного массива

Дальше речь пойдёт о самой распространённой реализации, хеш-таблицах, об их устройстве и о приёмах, накопленных разработчиками.

Но сначала давай рассмотрим простейший способ реализации ассоциативного массива, заведя обыкновенный массив или список с записанными в него парами `(key, value)`.

Если нужно получить элемент по ключу, достаточно пройти по всем элементам списка, выбрать пару с подходящим ключом и вернуть значение, записанное в этой паре. Если значение нужно сохранить, ищем пару с указанным ключом и, найдя её, изменяем хранимое там. А если пара с заданным ключом не нашлась, создаём новую и добавляем в конец массива, растущего по мере надобности.

```python
class NaiveMap:
    def __init__(self):
        self.pairs = []

    def get(self, key):
        for stored_key, value in self.pairs:
            if stored_key == key:  # пара с указанным ключом найдена
                return value
        return None

    def set(self, key, value):
        for i, (stored_key, _) in enumerate(self.pairs):
            if stored_key == key:  # пара с указанным ключом найдена
                # обновить значение в найденной паре
                self.pairs[i] = (key, value)
                return
        # пара с заданным ключом не найдена
        self.pairs.append((key, value))
```

Реализация, набросанная выше, получилась очень медленной, потому что на поиск элемента в таком массиве уходит в среднем \\(O(n)\\) операций. Дальше мы поговорим о том, как реализовать отображение более эффективным способом, при помощи хеш-таблиц.

## Что такое хеш-таблица и хеш-функция

Хеш-таблица (англ. hash table) — один из способов реализовать ассоциативный массив, при котором все данные, доверяемые структуре, хранятся в виде пар `(key, value)`, разложенных по ячейкам обыкновенного массива. Эти ячейки называются корзинами (англ. bucket) и, как и в любом массиве, пронумерованы. Индекс, или номер корзины, отведённой под данные, зависит от ключа, поэтому можно завести специальную функцию, которая вычисляет этот номер прямо по ключу, без всякого перебора.

### Как работают хеш-функция и хеш-таблица

Разберёмся, как сделать функцию, отвечающую нашим нуждам. Если у нас всего три ключа, мы можем написать несколько условных операторов, определяющих номер корзины. Но если ключей много, функция, собранная из таких проверок, разрастётся и будет работать медленно, а каждый добавленный ключ потребует новой строки.

Эта проблема решается с помощью специальной техники, называемой «хешированием», для которой нам понадобится хеш-функция.

Хеш-функцией (англ. hash function) называют функцию, превращающую входные данные в целое число, причём для объектов разного типа берутся разные хеш-функции. Число, полученное на выходе, называется «хешем» или «хеш-суммой» (англ. hash, hash code или digest), и именно оно определяет судьбу ключа.

Представим, что у каждой буквы алфавита есть свой индекс, равный её порядковому номеру. Хеш-функция может возвращать значение, совпадающее с индексом первой буквы, взятой из названия ключа. Тогда, например, для яблока функция вернёт 33, для груши 4, а для сливы 19.

```text
   ключ      первая буква   хеш
   ────      ────────────   ───
   яблоко         я          33
   груша          г           4
   слива          с          19
```

Так как хеш — целое число, оно годится на роль номера корзины и без преобразований, необходимых в общем случае. Например, информация про груши хранится в корзине 4, а значит, когда нам нужно получить или обновить число груш, привезённых на склад, достаточно заглянуть в ячейку, закреплённую за ними. При этом нам не требуется запоминать номера ячеек, вычисляемые хеш-функцией в любой момент.

```text
   корзины
   ┌────┬───────────────────┐
   │  4 │ груша: 120 кг     │  ← сюда попадает «груша»
   ├────┼───────────────────┤
   │ 19 │ слива: 45 кг      │
   ├────┼───────────────────┤
   │ 33 │ яблоко: 300 кг    │
   └────┴───────────────────┘
```

Другой пример хеш-функции: мы можем возвращать сумму всех номеров букв, входящих в название фрукта. Тогда для «яблоко» значение, посчитанное таким способом, будет 92, для «груша» 70, а для «слива» 46.

Многие хеш-функции выдают огромные числа: миллионы, миллиарды, а иногда и ещё больше. Поэтому хеш редко берётся напрямую как номер ячейки и чаще всего служит промежуточной стадией вычисления, разбитого надвое. Сначала по ключу мы определяем хеш, а затем из полученного хеша выводим номер корзины, отводимой под пару.

Пусть корзин \\( M = 11 \\), а хеш берётся второй функцией — суммой номеров букв.
Для «груши» она даёт 70, и остаток \\( 70 \bmod 11 = 4 \\):

```text
   ключ  ──[хеш-функция]──▶  хеш  ──[% M]──▶  номер корзины  ──▶  значение
  «груша»                     70              70 % 11 = 4          120 кг
```

Число корзин здесь другое, чем в картинке, нарисованной выше: там номером служил сам хеш по
первой букве, и корзин требовалось не меньше тридцати четырёх. В этом и смысл
остатка, позволяющего держать таблицу любого удобного размера независимо от
того, какие числа выдаёт хеш-функция, выбранная тобой.

*Отображение из ключа в значение разделилось на три независимых отображения. 1. Сначала хеш-функция отображает ключ в число, то есть в хеш. 2. Затем полученный хеш преобразуется в индекс корзины. 3. И, наконец, из массива корзин мы находим нужную по её индексу. В ней-то и лежит значение, возвращаемое пользователю.*

### Что такое коллизии

Ситуация, при которой хеш-функция для разных входных данных выдаёт одно и то же значение, называется «коллизией».

Например, и у «арбуза», и у «абрикоса» хеш, посчитанный по первой букве, равен 1, из-за чего оба ключа указывают на одну и ту же корзину, выделенную в хеш-таблице.

Коллизии случаются у всех без исключения хеш-функций, поэтому в любой хеш-таблице должен быть заложен способ, разрешающий их. Способов два.

При **методе цепочек** в корзине лежит не одна пара, а связный список всех пар, относимых к этому номеру. Вычисляем корзину, а внутри неё перебираем список, привязанный к ней. При **открытой адресации** пара кладётся в ближайшую свободную корзину, скажем в следующую по порядку; поиск идёт по правилу, выбранному при вставке, пока не встретится нужный ключ или ячейка, не занятая никем.

В обоих случаях цена операции зависит от числа ключей, делящих одну корзину. Пока хеш-функция раскидывает ключи равномерно, а корзин хватает, цепочки остаются короткими, и поиск, вставка и удаление стоят в среднем \\(O(1)\\) — та самая сложность, ради которой словарём пользуются не задумываясь. Если же коллизий много, хеш-таблица вырождается в список пар, с которого мы начинали, и поиск снова обходится в \\(O(n)\\), теряя всё преимущество, полученное хешированием. Поэтому дальше разберём, как выбрать число корзин и саму функцию так, чтобы коллизий, отравляющих жизнь, было поменьше.

### Коэффициент заполнения и перехеширование

Условие «корзин хватает» звучит расплывчато, поэтому его превращают в число. Отношение количества ключей, сложенных в таблицу, к количеству корзин называют коэффициентом заполнения (англ. load factor): пока он мал, цепочки коротки и почти все корзины пусты, а когда он подбирается к единице, ключи начинают тесниться и каждая операция обрастает перебором.

Поэтому таблица следит за собой сама. Как только коэффициент переваливает через порог, выбранный реализацией (в CPython это две трети), заводится новый массив корзин, в несколько раз больший прежнего, и все накопленные ключи раскладываются по нему заново: номер корзины ведь считается по модулю \\(M\\), а \\(M\\) изменилось, и старые номера разом потеряли смысл. Эту перестройку и называют перехешированием (англ. rehashing).

Стоит она \\(O(n)\\), но случается редко и с каждым разом всё реже, потому что таблица растёт не на одну корзину, а кратно. Ровно та же арифметика разобрана в главе [«Основные структуры данных»](./basic-structures.md) под заголовком «Реаллокация в динамических массивах»: редкие дорогие перестройки, размазанные по множеству дешёвых операций, дают амортизированную \\(O(1)\\), и это она стоит за константой, обещанной документацией.

## Выбор размера хеш-таблицы и вычисление номера корзины

### Вычисление номера корзины методом деления

Самый простой способ получить номер корзины \\(\mathrm{bucket}(k)\\) для целого ключа \\(k\\) состоит в том, чтобы взять остаток от деления, выполненного над \\(k\\) и числом корзин \\(M\\). Остаток от деления обозначается \\(k \bmod M\\) и произносится «\\(k\\) по модулю \\(M\\)». В языках программирования остаток вычисляется оператором `%`, встроенным в синтаксис.

Любое целое число \\(k\\) может быть представлено в форме \\(k = j\cdot M + r\\), где все числа целые, а \\(r \in[0,M)\\). Число \\(r\\), оставшееся после деления, и называется остатком.

Определение, данное так, нам удобно: остатки, полученные делением целого числа на \\(M\\), принимают значения, лежащие в диапазоне от \\(0\\) до \\((M-1)\\), и это как раз те же числа, что служат номерами корзин в хеш-таблице длины \\(M\\).

*Будь внимателен! В разных языках программирования остаток от деления по-разному работает с отрицательными числами ([см. подробности](https://en.wikipedia.org/wiki/Modulo_operation)). Не всегда это происходит так же, как математическая операция взятия по модулю. Например, выражение \\(-13 \bmod 5\\) в одних языках даст \\(2\\), в других \\(-3\\). Если не учесть эти нюансы, можно получить отрицательный номер корзины.*

### Выбор числа корзин

В качестве \\(M\\) нужно брать простое число, то есть делящееся без остатка только на себя и на 1. Причина у этого требования, поначалу неочевидного, чисто арифметическая.

Ключи могут быть неравномерно распределены не только в двоичной и десятичной системах счисления: есть много других закономерностей, которым они подчиняются, и далеко не все из них заметны глазу.

Чем больше делителей у \\(M\\), тем чаще закономерности, спрятанные в ключах, будут приводить к коллизиям. И наоборот, простое значение \\(M\\) уменьшает число столкновений, случающихся в корзинах, так как у простого числа всего два делителя.

*Для любого числа корзин можно придумать киллер-последовательность из ключей, подобранных так, чтобы коллизий случилось побольше. Но если делителей у M много, велик шанс наткнуться на такую последовательность случайно, а когда M выбрано большим простым числом, это маловероятно.*

### Вычисление номера корзины методом умножения

Ещё одним популярным способом вычисления номера ячейки служит метод умножения. Нам снова потребуется целое число, обозначенное на этот раз буквой \\(h\\), чтобы подчеркнуть, что это хеш ключа.
Пусть количество корзин равно \\(M\\), а также зададим константу \\(\alpha \in (0,1)\\).

Тогда \\(\mathrm{bucket}(h) = \left [ M \cdot \left \{ h \cdot \alpha \right \} \right ]\\) , где \\(\left [ x \right ]\\) обозначает целую часть числа \\(x\\), а \\(\left \{ x \right \}\\) его дробную часть.

Алгоритм построения хеш-функции, опирающийся на метод умножения:
* Домножаем хеш ключа \\(h\\) на выбранную константу \\(\alpha\\).
* Берём от результата дробную часть. Получается значение из диапазона \\([0,1)\\). Важно, что числа, посчитанные для разных ключей, окажутся равномерно рассеяны.
* Домножаем полученное значение на размер таблицы \\(M\\). Числа получаются распределёнными в диапазоне \\([0, M)\\)
* Берём от результата целую часть. С равными вероятностями получаются числа от \\(0\\) до \\((M−1)\\), становящиеся номерами корзин. Корзины, заполняемые равномерно, дадут нам меньше коллизий.

Дональд Кнут показал, что хеш-функция получается хорошей, если брать в качестве \\(\alpha\\) число, обратное золотому сечению.
$$
\displaystyle \alpha = \phi^{-1} = \left ( \frac{\sqrt 5 -1}{2} \right ) = 0.6180339887...
$$

## Свойства хеш-функций

Не любая функция подходит на роль хеш-функции. Как мы выяснили, нам нужна функция, принимающая на вход данные и выдающая число, отвечающее индексу корзины. Чтобы сформулировать основные свойства хеш-функций, давай вспомним, зачем эти функции нужны.

При работе с разными объектами нам важно быстро находить место, отведённое им в хеш-таблице. Благодаря хешу, вычисляемому за считаные операции, мы можем эффективно обновлять информацию, связанную с объектами: искать их, добавлять или удалять.

Например, пусть нам нужно выяснить стоимость товара в магазине. Если функция потратит на вычисление позиции элемента больше времени, чем ушло бы на последовательный перебор всех товаров, выложенных на полки, то смысла в применении такой функции нет.

Функция, преобразующая ключ в индекс корзины, должна обладать такими свойствами:

* **Детерминизм.** Для одного и того же ключа функция всегда должна возвращать одинаковое значение. Если внутри берётся случайное число, то повторный вызов может выдать новый индекс ячейки, а значит, мы не сможем достать искомые данные, спрятанные в хеш-таблице. Хорошая функция при повторном вызове выполняет те же действия, что и при первичном. Например, взятие числа по модулю другого числа остаётся детерминированной функцией, так как результат, посчитанный дважды, не изменится.
* **Эффективность.** Хеш-функция, вызываемая на каждой операции, должна вычисляться достаточно быстро. Сложность операции поиска складывается из сложности вычисления хеша и сложности поиска данных по хешу. Важно, чтобы оба процесса выполнялись эффективно.
* **Ограниченность.** Результат вычисления функции должен принадлежать диапазону, задаваемому размером хеш-таблицы. Поэтому обычно сначала вычисляют хеш-функцию, возвращающую произвольное число. А потом полученный результат берут по модулю \\(M\\), равного размеру хеш-таблицы. Таким образом, любой ключ окажется в интервале от \\(0\\) до \\(M-1\\), а значит, мы никогда не обратимся к индексу, не отвечающему ни одной из корзин.
* **Равномерность.** Данные должны быть распределены по хеш-таблице равномерно, то есть каждое выходное значение равновероятно. Равновероятность значит, что если мы запустим функцию для каждого элемента из большого списка разных объектов, то получим примерно равное число ответов, приходящихся на каждое значение от \\(0\\) до \\(M-1\\). В противном случае в какие-то ячейки мы будем пытаться записать значение чаще, чем в остальные, и это замедлит обращение к таблице. Примером неравномерной функции служит среднесуточная температура, взятая по городу и дате: большую часть времени она держится на одном и том же уровне, а аномальные морозы или жара случаются редко.

Мы рассмотрели 4 свойства, важных при реализации хеш-таблиц. Но хеширование используется и в других задачах, например для хранения паролей, проверки неизменности файла в процессе передачи, шифрования сообщений при передаче по сети. Для этих задач выделяют ещё несколько свойств, полезных хеш-функциям.

* **Лавинность.** При незначительном изменении входных данных выходное значение должно меняться значительно. При хешировании паролей функция, лишённая лавинности, взламывается проще. Если злоумышленник знает, что \\(h(aa) = 22\\), а \\(h(bb) = 33\\), то он может предположить такой \\(password\\), что \\(h(password) = 44\\). Перебрав небольшое число вариантов, он подберёт пароль по его хешу.
* **Необратимость.** Невозможно восстановить ключ по значению, выданному функцией. Например, при регистрации на сайте пользователь вводит свой пароль, к которому применяется хеш-функция. Полученный хеш записывается в базу данных, в ячейку, закреплённую за этим пользователем. Каждый раз, когда пароль вводится заново, к нему применяется та же функция. Так как алгоритм, взятый в обоих случаях, одинаков, новый хеш совпадёт с записью, сохранённой в базе, если пользователь ввёл свой исходный пароль. Даже если злоумышленник получит доступ к базе, у него не должно быть возможности восстановить пароль по украденным хешам.


## Построение хеш-функций для строк

Теперь посмотрим, как вычисляют хеш-функции для строк. Для этого
есть специальный алгоритм, называемый «полиномиальным хешированием» (от слова «полином», то есть многочлен). Хеш строки \\(s\\), составленной из символов, вычисляется по формуле:
$$
h(s)=\left(s_{1} q^{n-1}+s_{2} q^{n-2}+\cdots+s_{n-1} q+s_{n}\right) \bmod R
$$
Здесь \\(s_i\\) обозначает код \\(i\\)-го символа (например, ASCII-код), \\(n\\) — длину строки, а \\(R\\) и \\(q\\) — выбранные константы.

Все вычисления производятся по модулю некоторого большого числа \\(R\\), поскольку для длинных строк сумма, записанная в скобках, оказывается слишком большой для типа, отведённого под неё. В большинстве языков программирования при этом произойдёт переполнение типа целых чисел. В языках с реализованной «длинной арифметикой» переполнения не случится, но с ростом чисел, складываемых и перемножаемых в формуле, вычисления будут становиться всё медленнее.

Выбор числа \\(R\\) зависит от типа переменной, отведённой под хеши. Например, для беззнаковых 4-байтовых целых чисел удобно выбрать \\(R=2^{32}\\), а для 8-байтовых, вмещающих куда больше, можно взять \\(R=2^{64}\\).

Если строки длинные, выбор величины \\(q\\) не так важен, ведь в сумму войдут значения \\(q\\), возведённые в достаточно большие степени. Но ради универсальности лучше и здесь взять большое число, причём \\(q\\) должно быть не только большим, но и простым.

Вспомни: номер корзины получается как остаток от деления хеша на число корзин.
Чем меньше общих делителей у \\(q\\), \\(M\\) и \\(R\\), тем реже будут возникать коллизии. В качестве \\(R\\) мы уже договорились использовать \\(2^{32}\\), поэтому любое нечётное число не будет иметь с \\(R\\) общих делителей.

Число \\(M\\) меняется вслед за размером хеш-таблицы, ещё не известным в момент вычисления хеша. Из-за этого мы не можем гарантировать, что параметр \\(q\\), заданный заранее, и число корзин \\(M\\) окажутся взаимно простыми. Но выбор большого простого числа в качестве \\(q\\) делает вероятность нетривиальных общих делителей очень небольшой, поскольку у простого числа нет делителей, кроме него самого и единицы. Как мы говорили, \\(M\\) обычно тоже делают простым, поэтому общие делители появятся, только когда \\(M=q\\).

## Собираем хеш-таблицу на цепочках

Разобранного хватает, чтобы сложить работающую структуру. Возьмём одиннадцать корзин, число простое и маленькое, чтобы коллизии было видно невооружённым глазом, а хеш будем считать той самой суммой номеров букв, с которой начинали разговор про склад с фруктами:

```python
ALPHABET = 'абвгдеёжзийклмнопрстуфхцчшщъыьэюя'


def letters_hash(key):
    # Хеш — сумма номеров букв, входящих в ключ
    return sum(ALPHABET.index(letter) + 1 for letter in key)


class HashMap:
    def __init__(self, buckets_count=11):
        # В каждой корзине лежит список пар: это и есть метод цепочек
        self.buckets = [[] for _ in range(buckets_count)]

    def _bucket(self, key):
        # Хеш превращается в номер корзины остатком от деления
        return self.buckets[letters_hash(key) % len(self.buckets)]

    def get(self, key):
        # Перебираем цепочку, привязанную к корзине, а не всю таблицу
        for stored_key, value in self._bucket(key):
            if stored_key == key:
                return value
        return None

    def set(self, key, value):
        bucket = self._bucket(key)
        for i, (stored_key, _) in enumerate(bucket):
            if stored_key == key:
                bucket[i] = (key, value)
                return
        bucket.append((key, value))
```

Проверим на складе, посчитанном раньше. У «груши» сумма номеров букв равна 70, и остаток \\( 70 \bmod 11 = 4 \\), а у «яблока» сумма 92, и остаток \\( 92 \bmod 11 = 4 \\) — тот же самый. Вот тебе коллизия, устроенная нарочно: два ключа делят одну корзину, и оба лежат в ней списком, не мешая друг другу:

```python
warehouse = HashMap()
warehouse.set('груша', 120)
warehouse.set('яблоко', 300)

print(letters_hash('груша') % 11)   # 4
print(letters_hash('яблоко') % 11)  # 4
print(warehouse.buckets[4])         # [('груша', 120), ('яблоко', 300)]
print(warehouse.get('яблоко'))      # 300
```

Своя хеш-функция понадобилась здесь только ради наглядности. В настоящем коде хеш строки считает встроенная `hash`, и номер корзины получается тем же остатком:

```python
bucket_index = hash('груша') % 11
```

Печатать результат этого выражения бессмысленно: для строк Python подмешивает в хеш случайную соль, выбираемую при запуске интерпретатора, поэтому от запуска к запуску число будет разным. Сделано это против атак, забрасывающих сервер ключами, подобранными под одну корзину, и на работу словаря внутри одного процесса никак не влияет: там хеш, посчитанный дважды, всегда совпадает сам с собой, а больше от него ничего и не требуется.

## Поисковый индекс

Напомним основной принцип хеш-таблиц. Знаешь, куда был положен элемент, там его и ищи. Правило, выведенное из устройства таблицы, часто применяют для быстрого поиска по данным, накопленным заранее.

Представь, что ты пишешь программу для чтения, и одной из её функций должен стать поиск, идущий по тексту. Пользователь вводит слово или строку, а программа находит и показывает позиции, занятые ими в тексте.

Можно реализовать программу, описанную выше, с помощью хеш-таблицы, в которой ключами будут строки, а значениями массивы позиций, найденных для каждой строки.

Отображение, которое ставит каждому объекту в соответствие его расположение, называют «поисковым индексом», построенным по тексту.

Если пользователь введёт любую подстроку, хеш-таблица должна найти её позиции, а значит, нужно предварительно добавить туда все подстроки, встречаемые в тексте. А если подстроки, набранной пользователем, в таблице не оказалось, получается, и в тексте её нет.

Позицию мы получим сразу, и это, конечно, хорошо. Но способ, который мы только что придумали, крайне расточителен по памяти, занимаемой индексом. Подстрок в тексте столько, сколько существует способов выбрать две границы: \\(N\cdot(N+1)/2\\), где \\(N\\) — длина текста. Значит, в хеш-таблицу нужно добавить \\(O(N^2)\\) пар `(key, value)`. Поскольку ключами служат сами подстроки, каждая пара, положенная в корзину, займёт в среднем \\(O(N)\\) памяти. Получается, что всего при такой реализации придётся потратить \\(O(N^3)\\) памяти.

Поэтому с большими текстами реализация, построенная на подстроках, не сработает.

На практике индексируют не все подстроки, а слова, различимые по пробелам. Текст разбивается на слова, и в хеш-таблицу кладутся пары из слова и списка его позиций. Таких пар уже \\(O(N)\\), памяти нужно линейно, а поиск, идущий по целому слову, остаётся мгновенным. Так устроены и поисковые системы, и полнотекстовый поиск, встроенный в базы данных, только вместо простого списка позиций там хранятся структуры, устроенные куда хитрее.

## Резюме

* Хеш-таблица превращает поиск по ключу в вычисление: хеш-функция считает по ключу число, остаток от деления этого числа на количество корзин даёт номер ячейки, а дальше работает обычный массив.
* Коллизии неизбежны у любой хеш-функции, и разрешают их либо методом цепочек, складывая в корзину список пар, либо открытой адресацией, отправляя пару в ближайшую свободную ячейку.
* Обещанная \\(O(1)\\) держится на двух условиях: хеш-функция раскидывает ключи ровно, а корзин хватает. Второе обеспечивает перехеширование, стоящее \\(O(n)\\) на редких перестройках и потому не портящее среднюю цену.
* От хеш-функции требуют детерминизма, эффективности, ограниченности и равномерности, а от криптографической вдобавок лавинности и необратимости.
* Число корзин берут простым, чтобы закономерности, спрятанные во входных ключах, не сходились раз за разом в одну ячейку.
* Строки хешируют полиномиально, по модулю большого числа \\(R\\), выбранного взаимно простым с основанием \\(q\\) и числом корзин.
* Поисковый индекс — та же хеш-таблица, где ключом служит слово, а значением список его позиций; на нём стоит и полнотекстовый поиск в базах данных.
