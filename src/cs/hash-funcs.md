# Хеш-функции

Массив хорош тем, что даёт мгновенный доступ по номеру, вычисленному заранее. Но искать нередко приходится не по номеру, а по имени, будь то название города, идентификатор события, записанного детектором, или имя файла, сохранённого на диске.

Перебирать всё подряд слишком медленно. Номер ячейки, отведённой под пару, можно **вычислять** прямо из ключа. Этим занимаются хеш-функции, на которых построены словари и множества.

В этой главе разберём, как ключ превращается в номер корзины, почему разные ключи иногда попадают в одну корзину, что делать со столкнувшимися ключами и откуда у словаря берётся сложность \\(O(1)\\).

## Что такое отображение
В интерфейсе массива, разобранном в главе про структуры данных, есть две основные операции:

* `get(index: int) -> value` возвращает значение `value` из ячейки с индексом `index`;
* `set(index: int, value: ValueType)` записывает значение `value` в ячейку с индексом `index`.

Каждая из этих операций выполняется за \\(O(1)\\). Но у массивов есть ограничение, накладываемое устройством памяти: в ячейках можно расположить объекты любого типа, а индексы могут быть только целыми числами.

В программе часто нужно получить объект не по порядковому номеру, а по другому признаку, например по названию, или, как говорят программисты, получить значение (англ. value) по ключу (англ. key).

Пусть есть множество городов и множество стран, причём одному городу отвечает единственная страна.

```text
   города                страны
   ──────                ──────
   Новосибирск  ──┐
   Москва       ──┼───▶  Россия
   Казань       ──┘
   Минск        ─────▶   Беларусь
   Астана       ─────▶   Казахстан
```

Нужно написать программу-справочник, узнающую по городу страну. Если справочник будет пополняться, пригодится функция, добавляющая новую пару «город, страна».

Здесь город служит ключом, а страна — значением: каждому городу отвечает одна страна, а на страну может указывать любое количество городов.

Сопоставление, устроенное так, что каждому объекту первого множества (множество городов) отвечает единственный объект второго (множество стран), называется «отображением» (англ. map).

*Отображение — другое название математического термина «функция», или «функциональная зависимость». Чаще всего функции отображают числа на оси X в числа на оси Y: для каждого числа из области определения можно выписать другое число — значение функции в этой точке.*

Массивы — тоже частный случай отображения, сопоставляющий целому числу любое значение. Например, массив `["яблоко", "груша", "яблоко"]` отдаёт по числам `0` и `2` строку `яблоко`, а по числу `1` строку `груша`.

Для работы с отображениями нужна похожая на массив структура данных, умеющая получать и сохранять значения:

* `get(key: KeyType) -> value` возвращает значение `value` по ключу `key`;
* `set(key: KeyType, value: ValueType)` записывает значение `value` по ключу `key`.

Но вместо целочисленного индекса она должна допускать ключ произвольного типа.

Интерфейс, описывающий две этих операции, называют `Map`, а любую структуру, которая его реализует, называют **«ассоциативным массивом»** (англ. associative array).

### Ассоциативные массивы

В большинстве языков программирования ассоциативные массивы встроены в язык.

Чаще всего их называют так же, как интерфейс, то есть `Map`, «отображение», или используют производные от слова «хеш-таблица»: `Hash`, `HashMap`, `HashTable` и даже просто `Table`. Эти названия подчёркивают способ реализации интерфейса отображения. Встречаются и другие: в Python ассоциативные массивы называют *«словарями»* (англ. dictionary).

Есть два популярных способа реализовать (имплементировать) отображение в памяти: хеш-таблицы, о которых эта глава, и деревья поиска, о которых следующая. В некоторых языках есть обе реализации: в Java это `HashMap` и `TreeMap`, а в C++ — `std::unordered_map` и `std::map`.

Во многих языках есть отдельный синтаксис для создания ассоциативного массива. В Python отображение реализовано типом `dict`, встроенным в интерпретатор.

### Наивная реализация ассоциативного массива

Простейший способ реализовать ассоциативный массив — завести обыкновенный массив или список пар `(key, value)`.

Чтобы получить элемент по ключу, проходим по всем элементам списка, находим пару с подходящим ключом и возвращаем её значение. Чтобы сохранить значение, ищем пару с указанным ключом и изменяем хранимое там, а если пара не нашлась, добавляем новую в конец массива.

```python
class NaiveMap:
    def __init__(self):
        self.pairs = []

    def get(self, key):
        for stored_key, value in self.pairs:
            if stored_key == key:  # пара с указанным ключом найдена
                return value
        return None

    def set(self, key, value):
        for i, (stored_key, _) in enumerate(self.pairs):
            if stored_key == key:  # пара с указанным ключом найдена
                # обновить значение в найденной паре
                self.pairs[i] = (key, value)
                return
        # пара с заданным ключом не найдена
        self.pairs.append((key, value))
```

Такая реализация медленная: на поиск элемента уходит в среднем \\(O(n)\\) операций.

## Что такое хеш-таблица и хеш-функция

Хеш-таблица (англ. hash table) — способ реализовать ассоциативный массив, при котором данные хранятся в виде пар `(key, value)`, разложенных по ячейкам обыкновенного массива. Эти ячейки называются корзинами (англ. bucket) и пронумерованы. Номер корзины зависит от ключа, поэтому можно завести функцию, которая вычисляет этот номер прямо по ключу, без перебора.

### Как работают хеш-функция и хеш-таблица

Если ключей всего три, номер корзины можно определить несколькими условными операторами. Но если ключей много, функция из таких проверок разрастётся и будет работать медленно, а каждый добавленный ключ потребует новой строки.

Эта проблема решается хешированием, для которого нужна хеш-функция.

Хеш-функцией (англ. hash function) называют функцию, превращающую входные данные в целое число, причём для объектов разного типа берутся разные хеш-функции. Число, полученное на выходе, называется «хешем» или «хеш-суммой» (англ. hash, hash code или digest).

Пусть у каждой буквы алфавита есть индекс, равный её порядковому номеру. Хеш-функция может возвращать индекс первой буквы ключа. Тогда для яблока функция вернёт 33, для груши 4, а для сливы 19.

```text
   ключ      первая буква   хеш
   ────      ────────────   ───
   яблоко         я          33
   груша          г           4
   слива          с          19
```

Так как хеш — целое число, оно годится на роль номера корзины без преобразований, необходимых в общем случае. Информация про груши хранится в корзине 4: чтобы получить или обновить число груш на складе, достаточно заглянуть в эту ячейку. Запоминать номера ячеек не требуется: хеш-функция вычислит их в любой момент.

```text
   корзины
   ┌────┬───────────────────┐
   │  4 │ груша: 120 кг     │  ← сюда попадает «груша»
   ├────┼───────────────────┤
   │ 19 │ слива: 45 кг      │
   ├────┼───────────────────┤
   │ 33 │ яблоко: 300 кг    │
   └────┴───────────────────┘
```

Другой пример хеш-функции — сумма номеров всех букв названия. Тогда для «яблоко» она даст 92, для «груша» 70, а для «слива» 46.

Многие хеш-функции выдают огромные числа: миллионы, миллиарды и больше. Поэтому хеш редко берётся напрямую как номер ячейки: сначала по ключу определяем хеш, а затем из хеша выводим номер корзины.

Пусть корзин \\( M = 11 \\), а хеш берётся второй функцией — суммой номеров букв.
Для «груши» она даёт 70, и остаток \\( 70 \bmod 11 = 4 \\):

```text
   ключ  ──[хеш-функция]──▶  хеш  ──[% M]──▶  номер корзины  ──▶  значение
  «груша»                     70              70 % 11 = 4          120 кг
```

Число корзин здесь другое, чем на картинке выше: там номером служил сам хеш по
первой букве, и корзин требовалось не меньше тридцати четырёх. Остаток позволяет держать таблицу любого удобного размера независимо от
того, какие числа выдаёт хеш-функция.

*Отображение из ключа в значение разделилось на три независимых отображения. 1. Сначала хеш-функция отображает ключ в число, то есть в хеш. 2. Затем полученный хеш преобразуется в индекс корзины. 3. Наконец, в массиве корзин находим нужную по индексу; в ней лежит значение.*

### Что такое коллизии

Ситуация, при которой хеш-функция для разных входных данных выдаёт одно и то же значение, называется «коллизией».

Например, и у «арбуза», и у «абрикоса» хеш, посчитанный по первой букве, равен 1, и оба ключа указывают на одну корзину.

Коллизии случаются у всех хеш-функций, поэтому в любой хеш-таблице должен быть способ их разрешать. Способов два.

При **методе цепочек** в корзине лежит не одна пара, а связный список всех пар, относимых к этому номеру. Вычисляем корзину и перебираем её список. При **открытой адресации** пара кладётся в ближайшую свободную корзину, скажем в следующую по порядку; поиск идёт по правилу, выбранному при вставке, пока не встретится нужный ключ или пустая ячейка.

В обоих случаях цена операции зависит от числа ключей, делящих одну корзину. Пока хеш-функция раскидывает ключи равномерно, а корзин хватает, цепочки остаются короткими, и поиск, вставка и удаление стоят в среднем \\(O(1)\\). Если же коллизий много, хеш-таблица вырождается в список пар, с которого мы начинали, и поиск снова обходится в \\(O(n)\\).

### Коэффициент заполнения и перехеширование

Условие «корзин хватает» превращают в число. Отношение количества ключей в таблице к количеству корзин называют коэффициентом заполнения (англ. load factor): пока он мал, цепочки коротки и почти все корзины пусты, а когда он подбирается к единице, ключи теснятся и каждая операция обрастает перебором.

Как только коэффициент переваливает через порог, выбранный реализацией (в CPython это две трети), заводится новый массив корзин, в несколько раз больший прежнего, и все ключи раскладываются по нему заново: номер корзины считается по модулю \\(M\\), а \\(M\\) изменилось. Эту перестройку называют перехешированием (англ. rehashing).

Стоит она \\(O(n)\\), но случается редко и с каждым разом всё реже, потому что таблица растёт не на одну корзину, а кратно. Та же арифметика разобрана в главе [«Основные структуры данных»](./basic-structures.md) под заголовком «Реаллокация в динамических массивах»: редкие дорогие перестройки, размазанные по множеству дешёвых операций, дают амортизированную \\(O(1)\\).

## Выбор размера хеш-таблицы и вычисление номера корзины

### Вычисление номера корзины методом деления

Самый простой способ получить номер корзины \\(\mathrm{bucket}(k)\\) для целого ключа \\(k\\) — взять остаток от деления \\(k\\) на число корзин \\(M\\). Остаток от деления обозначается \\(k \bmod M\\) и произносится «\\(k\\) по модулю \\(M\\)». В языках программирования остаток вычисляется оператором `%`.

Любое целое число \\(k\\) может быть представлено в форме \\(k = j\cdot M + r\\), где все числа целые, а \\(r \in[0,M)\\). Число \\(r\\) и называется остатком.

Остатки от деления на \\(M\\) лежат в диапазоне от \\(0\\) до \\((M-1)\\) — те же числа, что служат номерами корзин в хеш-таблице длины \\(M\\).

*В разных языках программирования остаток от деления по-разному работает с отрицательными числами ([см. подробности](https://en.wikipedia.org/wiki/Modulo_operation)), не всегда так, как математическая операция взятия по модулю. Например, выражение \\(-13 \bmod 5\\) в одних языках даст \\(2\\), в других \\(-3\\). Если этого не учесть, можно получить отрицательный номер корзины.*

### Выбор числа корзин

В качестве \\(M\\) нужно брать простое число, то есть делящееся без остатка только на себя и на 1.

Ключи могут быть распределены неравномерно не только в двоичной и десятичной системах счисления: есть много других закономерностей, и не все они заметны глазу.

Чем больше делителей у \\(M\\), тем чаще закономерности в ключах приводят к коллизиям; у простого числа делителей всего два, поэтому простое \\(M\\) уменьшает число столкновений.

*Для любого числа корзин можно придумать киллер-последовательность ключей, дающую много коллизий. Но если делителей у M много, велик шанс наткнуться на такую последовательность случайно, а при большом простом M это маловероятно.*

### Вычисление номера корзины методом умножения

Другой популярный способ вычисления номера ячейки — метод умножения. Целое число обозначим на этот раз буквой \\(h\\), чтобы подчеркнуть, что это хеш ключа.
Пусть количество корзин равно \\(M\\), а также зададим константу \\(\alpha \in (0,1)\\).

Тогда \\(\mathrm{bucket}(h) = \left [ M \cdot \left \{ h \cdot \alpha \right \} \right ]\\) , где \\(\left [ x \right ]\\) обозначает целую часть числа \\(x\\), а \\(\left \{ x \right \}\\) его дробную часть.

Алгоритм построения хеш-функции, опирающийся на метод умножения:
* Домножаем хеш ключа \\(h\\) на выбранную константу \\(\alpha\\).
* Берём от результата дробную часть. Получается значение из диапазона \\([0,1)\\). Числа для разных ключей окажутся равномерно рассеяны.
* Домножаем полученное значение на размер таблицы \\(M\\). Числа получаются распределёнными в диапазоне \\([0, M)\\)
* Берём от результата целую часть. С равными вероятностями получаются числа от \\(0\\) до \\((M−1)\\) — номера корзин. Равномерно заполняемые корзины дают меньше коллизий.

Дональд Кнут показал, что хеш-функция получается хорошей, если брать в качестве \\(\alpha\\) число, обратное золотому сечению.
$$
\displaystyle \alpha = \phi^{-1} = \left ( \frac{\sqrt 5 -1}{2} \right ) = 0.6180339887...
$$

## Свойства хеш-функций

Не любая функция подходит на роль хеш-функции. Нужна функция, принимающая на вход данные и выдающая число, отвечающее индексу корзины.

Хеш, вычисляемый за считаные операции, позволяет быстро находить место объекта в хеш-таблице: искать его, добавлять или удалять.

Например, пусть нужно выяснить стоимость товара в магазине. Если функция потратит на вычисление позиции элемента больше времени, чем ушло бы на перебор всех товаров на полках, смысла в ней нет.

Функция, преобразующая ключ в индекс корзины, должна обладать такими свойствами:

* **Детерминизм.** Для одного и того же ключа функция всегда возвращает одинаковое значение. Если внутри берётся случайное число, повторный вызов может выдать новый индекс ячейки, и данные из хеш-таблицы будет не достать. Например, взятие числа по модулю другого числа детерминировано: результат, посчитанный дважды, не изменится.
* **Эффективность.** Хеш-функция, вызываемая на каждой операции, должна вычисляться быстро. Сложность операции поиска складывается из сложности вычисления хеша и сложности поиска данных по хешу.
* **Ограниченность.** Результат функции должен принадлежать диапазону, задаваемому размером хеш-таблицы. Поэтому обычно сначала вычисляют хеш-функцию, возвращающую произвольное число, а потом берут результат по модулю \\(M\\), равного размеру хеш-таблицы. Тогда любой ключ окажется в интервале от \\(0\\) до \\(M-1\\), и мы не обратимся к индексу, не отвечающему ни одной из корзин.
* **Равномерность.** Данные должны быть распределены по хеш-таблице равномерно, то есть каждое выходное значение равновероятно: запустив функцию для каждого элемента большого списка разных объектов, получим примерно равное число ответов на каждое значение от \\(0\\) до \\(M-1\\). Иначе в какие-то ячейки запись пойдёт чаще, чем в остальные, и обращение к таблице замедлится. Пример неравномерной функции — среднесуточная температура по городу и дате: большую часть времени она держится на одном уровне, а аномальные морозы или жара случаются редко.

Хеширование используется и в других задачах: для хранения паролей, проверки неизменности файла при передаче, шифрования сообщений в сети. Для них выделяют ещё несколько свойств.

* **Лавинность.** При незначительном изменении входных данных выходное значение должно меняться значительно. При хешировании паролей функция, лишённая лавинности, взламывается проще. Если злоумышленник знает, что \\(h(aa) = 22\\), а \\(h(bb) = 33\\), то он может предположить такой \\(password\\), что \\(h(password) = 44\\). Перебрав небольшое число вариантов, он подберёт пароль по его хешу.
* **Необратимость.** Невозможно восстановить ключ по значению функции. Например, при регистрации на сайте к паролю пользователя применяется хеш-функция, и полученный хеш записывается в базу данных. Каждый раз, когда пароль вводится заново, к нему применяется та же функция, и новый хеш совпадёт с записью в базе, если введён исходный пароль. Даже получив доступ к базе, злоумышленник не должен иметь возможности восстановить пароль по украденным хешам.


## Построение хеш-функций для строк

Хеш-функции для строк вычисляют «полиномиальным хешированием» (от слова «полином», то есть многочлен). Хеш строки \\(s\\) вычисляется по формуле:
$$
h(s)=\left(s_{1} q^{n-1}+s_{2} q^{n-2}+\cdots+s_{n-1} q+s_{n}\right) \bmod R
$$
Здесь \\(s_i\\) обозначает код \\(i\\)-го символа (например, ASCII-код), \\(n\\) — длину строки, а \\(R\\) и \\(q\\) — выбранные константы.

Все вычисления производятся по модулю большого числа \\(R\\), поскольку для длинных строк сумма в скобках не помещается в целочисленный тип: в большинстве языков программирования произойдёт переполнение. В языках с «длинной арифметикой» переполнения не случится, но с ростом чисел вычисления будут замедляться.

Выбор числа \\(R\\) зависит от типа переменной, отведённой под хеши. Например, для беззнаковых 4-байтовых целых чисел удобно выбрать \\(R=2^{32}\\), а для 8-байтовых можно взять \\(R=2^{64}\\).

Если строки длинные, выбор величины \\(q\\) не так важен, ведь в сумму войдут значения \\(q\\), возведённые в достаточно большие степени. Но ради универсальности лучше взять большое простое число.

Номер корзины получается как остаток от деления хеша на число корзин.
Чем меньше общих делителей у \\(q\\), \\(M\\) и \\(R\\), тем реже коллизии. В качестве \\(R\\) мы договорились использовать \\(2^{32}\\), поэтому любое нечётное число не будет иметь с \\(R\\) общих делителей.

Число \\(M\\) меняется вслед за размером хеш-таблицы, ещё не известным в момент вычисления хеша, поэтому нельзя гарантировать, что заданный заранее \\(q\\) и число корзин \\(M\\) окажутся взаимно простыми. Но большое простое \\(q\\) делает нетривиальные общие делители маловероятными, поскольку у простого числа нет делителей, кроме него самого и единицы. \\(M\\) обычно тоже делают простым, поэтому общие делители появятся, только когда \\(M=q\\).

## Собираем хеш-таблицу на цепочках

Возьмём одиннадцать корзин, число простое и маленькое, чтобы коллизии были видны, а хеш будем считать суммой номеров букв, как в примере со складом:

```python
ALPHABET = 'абвгдеёжзийклмнопрстуфхцчшщъыьэюя'


def letters_hash(key):
    # Хеш — сумма номеров букв, входящих в ключ
    return sum(ALPHABET.index(letter) + 1 for letter in key)


class HashMap:
    def __init__(self, buckets_count=11):
        # В каждой корзине лежит список пар: это и есть метод цепочек
        self.buckets = [[] for _ in range(buckets_count)]

    def _bucket(self, key):
        # Хеш превращается в номер корзины остатком от деления
        return self.buckets[letters_hash(key) % len(self.buckets)]

    def get(self, key):
        # Перебираем цепочку, привязанную к корзине, а не всю таблицу
        for stored_key, value in self._bucket(key):
            if stored_key == key:
                return value
        return None

    def set(self, key, value):
        bucket = self._bucket(key)
        for i, (stored_key, _) in enumerate(bucket):
            if stored_key == key:
                bucket[i] = (key, value)
                return
        bucket.append((key, value))
```

У «груши» сумма номеров букв равна 70, и остаток \\( 70 \bmod 11 = 4 \\), а у «яблока» сумма 92, и остаток \\( 92 \bmod 11 = 4 \\) — тот же. Это коллизия: два ключа делят одну корзину и лежат в ней списком:

```python
warehouse = HashMap()
warehouse.set('груша', 120)
warehouse.set('яблоко', 300)

print(letters_hash('груша') % 11)   # 4
print(letters_hash('яблоко') % 11)  # 4
print(warehouse.buckets[4])         # [('груша', 120), ('яблоко', 300)]
print(warehouse.get('яблоко'))      # 300
```

Своя хеш-функция понадобилась здесь только ради наглядности. В настоящем коде хеш строки считает встроенная `hash`, и номер корзины получается тем же остатком:

```python
bucket_index = hash('груша') % 11
```

Результат этого выражения от запуска к запуску разный: для строк Python подмешивает в хеш случайную соль, выбираемую при запуске интерпретатора. Сделано это против атак, забрасывающих сервер ключами, подобранными под одну корзину, и на работу словаря внутри одного процесса не влияет: там хеш, посчитанный дважды, совпадает сам с собой.

## Поисковый индекс

Основной принцип хеш-таблиц: знаешь, куда был положен элемент, там его и ищи. Это правило часто применяют для быстрого поиска по данным, накопленным заранее.

Пусть ты пишешь программу для чтения с поиском по тексту: пользователь вводит слово или строку, а программа показывает их позиции в тексте.

Её можно реализовать хеш-таблицей, в которой ключами будут строки, а значениями — массивы позиций.

Отображение, которое ставит каждому объекту в соответствие его расположение, называют «поисковым индексом».

Хеш-таблица должна находить позиции любой подстроки, а значит, в неё нужно заранее добавить все подстроки текста. Если подстроки в таблице нет, нет её и в тексте.

Позицию мы получим сразу, но этот способ расточителен по памяти. Подстрок в тексте столько, сколько способов выбрать две границы: \\(N\cdot(N+1)/2\\), где \\(N\\) — длина текста. Значит, в хеш-таблицу нужно добавить \\(O(N^2)\\) пар `(key, value)`. Поскольку ключами служат сами подстроки, каждая пара займёт в среднем \\(O(N)\\) памяти, а всего — \\(O(N^3)\\).

Поэтому с большими текстами реализация, построенная на подстроках, не сработает.

На практике индексируют не все подстроки, а слова, различимые по пробелам. Текст разбивается на слова, и в хеш-таблицу кладутся пары из слова и списка его позиций. Таких пар \\(O(N)\\), памяти нужно линейно, а поиск по целому слову остаётся мгновенным. Так устроены поисковые системы и полнотекстовый поиск в базах данных, только вместо списка позиций там хранятся более сложные структуры.

## Резюме

* Хеш-таблица превращает поиск по ключу в вычисление: хеш-функция считает по ключу число, остаток от деления этого числа на количество корзин даёт номер ячейки, а дальше работает обычный массив.
* Коллизии неизбежны у любой хеш-функции, и разрешают их либо методом цепочек, складывая в корзину список пар, либо открытой адресацией, отправляя пару в ближайшую свободную ячейку.
* Обещанная \\(O(1)\\) держится на двух условиях: хеш-функция раскидывает ключи ровно, а корзин хватает. Второе обеспечивает перехеширование, стоящее \\(O(n)\\) на редких перестройках и потому не портящее среднюю цену.
* От хеш-функции требуют детерминизма, эффективности, ограниченности и равномерности, а от криптографической вдобавок лавинности и необратимости.
* Число корзин берут простым, чтобы закономерности, спрятанные во входных ключах, не сходились раз за разом в одну ячейку.
* Строки хешируют полиномиально, по модулю большого числа \\(R\\), выбранного взаимно простым с основанием \\(q\\) и числом корзин.
* Поисковый индекс — та же хеш-таблица, где ключом служит слово, а значением список его позиций; на нём стоит и полнотекстовый поиск в базах данных.
