# Установка Arch Linux

Прочитать про загрузку системы и разметку дисков это одно, а собрать систему с нуля своими руками совсем другое. Для этого лучше всего подходит Arch Linux. Мастера в три клика тут нет; всё, спрятанное другими дистрибутивами за полосой прогресса, придётся проделать руками, шаг за шагом.

Ставить будем на виртуальную машину в VirtualBox, где ничего не жалко и всё повторяемо. Сначала соберём систему в режиме Legacy BIOS, потом разберём вариант с зеркальным RAID-массивом, собранным из двух дисков, а в конце переключим машину на UEFI и перенастроим загрузчик. Вечера на всё про всё хватит.

## Создание виртуальной машины

1. Открой VirtualBox и создай новую виртуальную машину.
2. Введи имя виртуальной машины и выбери тип операционной системы **Linux** и версию **Arch Linux (64-bit)**.
3. Выдели необходимое количество оперативной памяти (рекомендуется не менее 2 ГБ).
4. Создай новый виртуальный жёсткий диск и выбери формат VDI.
5. Выдели место на диске (рекомендуется не менее 20 ГБ).
6. В настройках виртуальной машины выбери **Legacy BIOS** (или **SeaBIOS**).
7. Выбери ISO образ Arch Linux.

## Установка Arch Linux с использованием Legacy BIOS

Дальше идёт последовательность команд, и смысл каждой стоит понимать, а не копировать вслепую. Логика, повторяющаяся у любого дистрибутива, такая. Разметить диск, создать на разделах файловые системы, смонтировать их в нужном порядке, распаковать туда базовую систему, войти в неё и поставить загрузчик.

1. Запусти виртуальную машину и загрузись с ISO образа Arch Linux.

2. Используй `cfdisk` для разметки диска (`/dev/sda`). Выбери таблицу разделов
   **GPT** и создай три раздела:
   - `/dev/sda1`: 1M, тип **BIOS boot** (код `EF02`)
   - `/dev/sda2`: 1G, тип **EFI System** (код `EF00`), то есть ESP
   - `/dev/sda3`: остальное пространство для корневой файловой системы

   Первый раздел выглядит лишним, но без него не обойтись. На диске с MBR GRUB
   прячет свою вторую ступень в промежутке, оставленном после загрузочной записи, а на GPT
   такого промежутка нет, и `grub-install --target=i386-pc` откажется работать
   с сообщением «embedding is not possible». Раздел BIOS boot и есть то место,
   куда GRUB её кладёт; файловой системы на нём не создают, он остаётся сырым.

   Второй раздел сейчас тоже не понадобится, поскольку при загрузке через BIOS
   прошивка про ESP ничего не знает. Он заведён на будущее, а в конце главы
   мы вернёмся к этой самой машине и переключим её на UEFI, и тогда
   переразмечать диск уже не придётся.

3. Создай файловую систему на ESP разделе.
   ```bash
   mkfs.fat -F32 /dev/sda2
   ```

4. Создай файловую систему на корневом разделе.
   ```bash
   mkfs.ext4 /dev/sda3
   ```

5. Смонтируй корневую файловую систему.
   ```bash
   mount /dev/sda3 /mnt
   ```

6. Создай и смонтируй ESP.
   ```bash
   mkdir /mnt/boot
   mount /dev/sda2 /mnt/boot
   ```

7. Установи базовую систему.
   ```bash
   pacstrap /mnt base linux linux-firmware
   ```

8. Сгенерируй файл fstab.
   ```bash
   genfstab -U /mnt >> /mnt/etc/fstab
   ```

9. Перейди в новую систему. Команда `arch-chroot` подменяет корень файловой
   системы на `/mnt`, и дальше всё выполняется так, как если бы ты уже загрузился
   в устанавливаемую систему. Механику подмены корня разберём в главе про
   внутреннее устройство Linux.
   ```bash
   arch-chroot /mnt
   ```

10. Установи загрузчик GRUB.
    ```bash
    pacman -S grub
    grub-install --target=i386-pc /dev/sda
    grub-mkconfig -o /boot/grub/grub.cfg
    ```

11. Установи пароль root.
    ```bash
    passwd
    ```

12. Выйди из chroot-окружения и размонтируй файловые системы.
    ```bash
    exit
    umount -R /mnt
    reboot
    ```

## Установка Arch Linux на RAID1

Тот же путь, но на зеркале из двух дисков. Отличий от обычной установки два. Массив нужно собрать до создания файловой системы, а initramfs — научить данный массив находить. Забыв второе, получишь собранную систему, которая при первой же загрузке не найдёт корень.

1. Добавь виртуальной машине второй диск такого же размера и загрузись с установочного образа Arch Linux.

2. Подготовь диски.
   ```bash
   cfdisk /dev/sda
   cfdisk /dev/sdb
   ```
   На каждом диске выбери таблицу **GPT** и создай два раздела: `/dev/sda1`
   размером 1M с типом **BIOS boot** (`EF02`) и `/dev/sda2` на всё остальное
   с типом **Linux RAID** (`FD00`); то же самое на `/dev/sdb`. Раздел BIOS boot
   нужен по той же причине, что и в предыдущем разделе, и нужен он на **обоих**
   дисках, иначе после отказа первого машина со второго не поднимется.

3. Создай RAID1 массив.
   ```bash
   mdadm --create --verbose /dev/md0 --level=1 --raid-devices=2 /dev/sda2 /dev/sdb2
   ```

4. Отформатируй RAID-массив.
   ```bash
   mkfs.ext4 /dev/md0
   ```

5. Смонтируй файловую систему.
   ```bash
   mount /dev/md0 /mnt
   ```

6. Установи базовую систему.
   ```bash
   pacstrap /mnt base linux linux-firmware mdadm
   ```

7. Сгенерируй fstab.
   ```bash
   genfstab -U /mnt >> /mnt/etc/fstab
   ```

8. Выполни chroot в новую систему.
   ```bash
   arch-chroot /mnt
   ```

9. Настрой mdadm.
   ```bash
   mdadm --detail --scan >> /etc/mdadm.conf
   ```

10. Настрой mkinitcpio:

    Открой `/etc/mkinitcpio.conf` и добавь `mdadm_udev` в список `HOOKS`, обязательно раньше `filesystems`, иначе к моменту монтирования корня массив ещё не будет собран.
    ```bash
    HOOKS=(base udev autodetect modconf block mdadm_udev filesystems keyboard fsck)
    ```

11. Пересобери начальный RAM-диск.
    ```bash
    mkinitcpio -P
    ```

12. Установи GRUB.
    ```bash
    pacman -S grub
    ```

13. Установи GRUB на оба диска.
    ```bash
    grub-install --target=i386-pc /dev/sda
    grub-install --target=i386-pc /dev/sdb
    ```

14. Создай конфигурацию GRUB.
    ```bash
    grub-mkconfig -o /boot/grub/grub.cfg
    ```

15. Перезагрузи систему.
    ```bash
    exit
    umount -R /mnt
    reboot
    ```

Проверить собранное зеркало стоит сразу. Выключи машину, отсоедини один диск, убедись, что система грузится, потом верни его на место и повтори со вторым. Массив, отказ которого ни разу не проверяли, ничем не лучше его отсутствия.

## Переключение на UEFI и настройка загрузчика

Возвращаемся к машине из первой установки, размеченной на sda1, sda2 и sda3: EFI-раздел там уже заведён и до сих пор простаивал. Зеркало из предыдущего раздела для этого шага не годится, потому что ESP в нём нет; связку RAID1 с UEFI ты соберёшь сам в задании.

Систему переустанавливать не придётся. UEFI отличается от BIOS только тем, где лежит загрузчик и как прошивка его находит, поэтому вся задача сводится к тому, чтобы положить `.efi`-файл на EFI-раздел и зарегистрировать созданную запись в NVRAM.

1. Останови виртуальную машину.
2. В настройках виртуальной машины измени BIOS на UEFI.
3. Запусти виртуальную машину и загрузись с ISO образа Arch Linux.

4. Смонтируй корневую файловую систему и ESP.
   ```bash
   mount /dev/sda3 /mnt
   mount /dev/sda2 /mnt/boot
   arch-chroot /mnt
   ```

5. Установи необходимые пакеты для загрузки с UEFI.
   ```bash
   pacman -S grub efibootmgr dosfstools os-prober mtools
   ```

6. Установи загрузчик GRUB с поддержкой UEFI.
   ```bash
   grub-install --target=x86_64-efi --efi-directory=/boot --bootloader-id=GRUB
   grub-mkconfig -o /boot/grub/grub.cfg
   efibootmgr -v
   ```

В выводе `efibootmgr -v` должна появиться запись GRUB. Если её нет, прошивка, ищущая загрузчик, ничего не найдёт, поэтому проверь, что раздел с `.efi`-файлом смонтирован в `/boot` и отформатирован в FAT32.


> **Задание.** Повтори установку самостоятельно, но с зеркалированием диска и загрузкой через UEFI: [«Установка Arch Linux вручную с RAID1 и UEFI»](../practicum/booting-linux-task.md).
