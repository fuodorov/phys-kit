# Мультиагентный помощник оператора

Эта глава — о программе, поставленной рядом с настоящей машиной и говорящей с оператором обычным языком.

## Задача

Человек, заступивший на смену в пультовой, зажат между тремя стопками сведений, никак между собой не связанными.

Первая стопка — приборы. Сотни мониторов и тысячи PV-переменных, названных по принятому в проекте регламенту вроде `ACC1:BI-LA1:PK3-fastAvX:Mea`. Имя, собранное из участка, устройства, измеряемой величины и вида обработки, читается однозначно, но держать в памяти тысячу таких имён нельзя. Чтобы посмотреть орбиту, надо знать и имена каналов, и панель, отведённую под них.

Вторая стопка — документация, разбросанная по вики, чертежам, статьям и инструкциям, накопленным за годы проектирования. Ответ на вопрос «как измерить эмиттанс» где-то записан, но найти его значит вспомнить, в каком документе он лежит, а документы, собранные разными коллективами за разные годы, единого оглавления не имеют.

Третья стопка — журнал смены, заполняемый вручную. Запись, сделанная в конце дежурства по памяти, всегда короче происходившего, а слово «успешно» в ней остаётся мнением, никем не проверенным.

Новичку тяжело, потому что три стопки приходится держать в голове разом, а опытный оператор перегружен рутиной.

**SAVA** — разговорный интерфейс к ускорителю, связывающий эти три вещи в одном окне. В отличие от остальных программ, разобранных в этой части книги, свидетельство о государственной регистрации на неё пока не оформлено.

## Как это собрано

Оператор говорит с системой из Telegram-бота, из веб-интерфейса или из терминала. Запрос попадает в **роутер** — сервис, спрашивающий у языковой модели, какой инструмент здесь нужен, и рассылающий команды агентам. Каждый агент занят одним делом и владеет одним хранилищем.

```
                       Telegram / Web / CLI
                                │
                                │ запрос
                                ▼
                          ┌───────────┐
                    ┌────▶│   Роутер  │◀────┐
                    │     └─────┬─────┘     │
              ответ │           │           │ ответ
        опрос,      │  докумен- │           │  запись
     управление     │   тация   │           │
            ┌───────┴───┐  ┌────▼──────┐  ┌─┴─────────┐
            │Контроллер │  │Консультант│  │ Секретарь │
            │   EPICS   │  │    RAG    │  │  журнал   │
            └─────┬─────┘  └─────┬─────┘  └─────┬─────┘
                  │              │              │
            ┌─────▼─────┐  ┌─────▼─────┐  ┌─────▼─────┐
            │   EPICS   │  │  Vector   │  │ PostgreSQL│
            │GetPV/SetPV│  │   Store   │  │           │
            └─────┬─────┘  └───────────┘  └───────────┘
                  │
            ┌─────▼─────┐
            │ Ускоритель│
            └───────────┘
```

Ответы, возвращаемые агентами, роутер собирает и отдаёт оператору одним сообщением. Агенты общаются сообщениями, передаваемыми через очереди Apache Kafka; сама механика очередей разобрана в главе про [сети и веб-технологии](../dev/web.md). Журнал смены лежит в PostgreSQL, устройство которого описано в главе про [базы данных](../dev/bd.md).

Внутри роутера два шага. Сперва модель, получившая историю разговора и список инструментов, называет подходящий; потом вызовы, названные ею, превращаются в команды, уходящие агентам. Инструментов, видимых модели, десять, и ещё пять остаются внутренними: график, голос и сводку смены заказывает сама система, не тратя на них решение модели. Результаты, приходящие от агентов, роутер сшивает в один ответ и отправляет туда, откуда пришёл запрос.

Специализаций, объявленных у системы, пять.

- **Консультант** ищет по документации через RAG и отвечает с указанием источника.
- **Секретарь** ведёт журнал смены: пишет и то, что сделала система, и то, что продиктовал оператор.
- **Контроллер** опрашивает PV и делает базовые проверки через EPICS.
- **Тренер** помогает учить новых операторов, разбирая с ними учебные ситуации.
- **Исследователь** помогает разбирать данные и готовить отчёты.

Состав системы объявлен один раз, в реестре. `ToolSpec` описывает инструмент, видимый языковой модели, а `AgentSpec` — сервис, исполняющий инструменты. Из реестра выводится всё остальное: схемы, отдаваемые модели, маршрутизация «инструмент → агент», список очередей и цели, опрашиваемые мониторингом.

```python
@dataclass(frozen=True)
class ToolSpec:
    """Инструмент: что видит модель и кто его исполняет."""

    name: str
    schema: dict | None = None      # None — внутренний, модели не показывается
    writes: bool = False            # трогает оборудование
    long_running: bool = False
    min_role: Role = Role.OPERATOR
```

*Описание инструмента в реестре, `sava_lib/registry.py`*

Инструмент, объявленный без схемы, модели не показывается: график рисует и голосом отвечает сама система, а не модель, решившая, что это уместно. Поле `min_role` задаёт наименьший уровень доступа: `knowledge` открывает одну документацию, `observer` разрешает смотреть и спрашивать, `operator` — работать с машиной. Научному руководителю, заглянувшему на смену, нужно чтение, а студенту хватит документации.

## Контроллер: опрос и управление

Агент — это набор функций, помеченных декоратором. Цикл опроса очереди, метрики, повторы и разбор ошибок живут в общем `AgentRunner`, и в самом агенте остаётся только работа.

```python
@runner.tool("GetPV")
def get(ctx: Ctx) -> dict:
    """Читает один PV."""
    pv_name = ctx.payload.get("pv_name", "")
    ctx.policy.enforce_read(pv_name)
    res = get_pv(pv_name, use_monitor=bool(ctx.payload.get("use_monitor", False)))
    return {"result": json.dumps(res, ensure_ascii=False)}


@runner.tool("SetPV")
def put(ctx: Ctx) -> dict:
    """Запись одного PV — только по конверту, подтверждённому оператором."""
    pv_name = ctx.payload.get("pv_name", "")
    value = float(ctx.payload.get("value"))
    if not bool(ctx.payload.get("confirmed", False)):
        raise PolicyError(f"Запись {pv_name} без подтверждения оператора.")
    applied = ctx.writer.put(pv_name, value, confirmed=True)
    return {"result": json.dumps({"pv_name": pv_name, "value": applied})}
```

*Чтение и запись переменной EPICS, `agents/pv-agent/main.py`*

Значение, отданное оператору, снабжено признаком достоверности: канал, не ответивший вовремя, даёт ошибку, а не подставленное умолчание. Самый частый разговор в пультовой выглядит так. Оператор называет датчики словами, модель превращает названное в вызовы `GetPV`, а показания, собранные с обоих каналов, пересказываются человеческим языком.

```
Оператор: Опроси датчики положения пучка
          BI-LA1:PK3-fastAvX:Mea, BI-LA2:PK4-fastAvX:Mea

Sava: -> GetPV("BI-LA1:PK3-fastAvX:Mea")  -> 0.15 мм
      -> GetPV("BI-LA2:PK4-fastAvX:Mea")  -> -0.08 мм

      Датчик PK3 показывает смещение 0.15 мм,
      PK4: -0.08 мм. Орбита близка к опорной.
```

Флаг `writes`, объявленный в реестре, делит инструменты надвое. Читающему хватает проверки политики, а пишущему выдаётся **конверт** — описание операции, собранное до разговора с оператором и подтверждаемое им целиком, одним «да». В конверте перечислены каналы, границы, назначенные каждому из них, предельное число записей и срок годности.

```python
@dataclass(frozen=True)
class WriteEnvelope:
    """Что операции разрешено записать, в каких границах и сколько раз."""

    envelope_id: str
    command_id: str
    purpose: str                      # «матрица отклика орбиты»
    bounds: tuple[WriteBound, ...]
    max_writes: int
    ttl_s: float = 1800.0

    def check(self, pv: str, value: float) -> None:
        """Проверка одной записи."""
        b = self.bound_for(pv)
        if b is None:
            raise PolicyError(f"{pv} не входит в состав операции «{self.purpose}».")
        if value < b.lo or value > b.hi:
            raise PolicyError(f"{pv}={value:g} вне границ [{b.lo:g}, {b.hi:g}].")
```

*Конверт записи, `sava_lib/write_guard.py`*

Подтверждается операция целиком, а не каждая запись по отдельности. Одна коррекция орбиты складывается из десятков `caput`, выполняемых подряд, и человек, замученный вопросами, перестанет их читать уже на пятом. Текст, показываемый оператору перед пуском, называет корректоры и пикапы поимённо, а не «сейчас поправлю орбиту», и рядом с каждым параметром помечено, взят он из умолчаний или из просьбы. Значение, вышедшее за объявленную границу, даёт отказ, а не обрезку до допустимого.

Коррекция, собранная из чтения, расчёта и двух записей, идёт так.

```
Оператор: Орбита в линаке смещена, помоги скорректировать

Sava: -> GetPV("BI-LA1:PK3-fastAvX:Mea")  -> 0.15 мм
      -> GetPV("BI-LA2:PK4-fastAvX:Mea")  -> -0.08 мм
      -> CalculateCorrection(0.15, -0.08)
         -> {"MG-LA1:CL1:HKICK": 0.5, "MG-LA1:CL2:HKICK": -0.3}
      -> SetPV("MG-LA1:CL1:HKICK", 0.5)
      -> SetPV("MG-LA1:CL2:HKICK", -0.3)

      Коррекция выполнена: MG-LA1:CL1:HKICK=0.5, MG-LA1:CL2:HKICK=-0.3.
      Проверьте новые показания датчиков.
```

Математика, спрятанная за строкой `CalculateCorrection`, — матрица отклика и разложение по сингулярным числам, разобранные в главе про [коррекцию равновесной орбиты](./orbit-correction.md).

## Консультант: поиск по документации

Корпус документации института нарезан на фрагменты примерно по пятьсот токенов, снабжённые заголовком и номером страницы, и уложен в векторный индекс. Вопрос оператора проходит пять ступеней.

```
1. Оператор: «Как измерить эмиттанс?»
        │
        ▼
2. Векторизация запроса
        │
        ▼                                Chunk 1: Ma Xiaochao, стр. 45
3. Поиск в Vector Store  ─────────────▶  Chunk 2: EPICS Wiki
   топ-3 фрагмента                       Chunk 3: регламент СКИФ
        │
        ▼
4. Добавление контекста в промпт
        │
        ▼
5. Модель отвечает с указанием источника
```

Третья ступень в репозитории двойная. Плотностной поиск по векторам сложен со списком, найденным классическим BM25, а два порядка слиты по правилу обратного ранга: слово, редко встречающееся в корпусе, так не теряется среди фрагментов, близких по смыслу. Инструмент, объявленный в реестре, называется `FileSearch`.

```
Оператор: Как измерить эмиттанс?

Sava: -> FileSearch("Как измерить эмиттанс?")
         Находит: Ma Xiaochao, стр. 45

      Ответ: Для измерения эмиттанса используйте метод...
      Источник: Ma Xiaochao, стр. 45
```

Ссылка на источник — обязательная часть ответа. Номер страницы, привязанный к фрагменту ещё при нарезке, доезжает до оператора, и тот открывает названное место сам. Про устройство инструментов, выдаваемых языковой модели, написано в главе [«Инструментарий»](../ai/instruments.md).

Сам корпус лежит в объектном хранилище и версионируется, а индекс, построенный по нему, кешируется там же. Подпись кеша складывается из корпуса, модели эмбеддингов и правил нарезки, так что документ, добавленный в корпус, вызывает перестроение индекса, а не тихое расхождение. Сторож, работающий в фоне, замечает обновление и перечитывает документы без перезапуска агента.

## Секретарь: журнал смены

Журнал наполняется из двух источников. Первый — сама система: каждая запись, применённая к оборудованию, попадает в журнал по факту, одной строкой на подтверждённое действие. Слово «успешно» тут не мнение модели, а то, чем кончился `caput`. Второй источник — оператор, рассказывающий о том, чего система не видит: о действиях у стойки, о наблюдениях, о разговорах со сменой.

```
Оператор: Я сделал 2 раза коррекцию орбиты
          в линейном ускорителе, запиши!

Sava: -> ActionRecord(
          action="Коррекция орбиты",
          system="Линейный ускоритель",
          details="Выполнено 2 итерации",
          result="Успешно")

      Записал в журнал: коррекция орбиты линака.
```

Поле `system` приводится к закрытому словарю подсистем. Название, полученное от модели, само по себе не годится: одна и та же подсистема называлась бы то «Орбита», то «Уставки машины», и группировка, собираемая по свободному тексту, разъехалась бы на первой же сотне записей. Поле с именем оператора модель не заполняет — его проставляет система поверх присланных аргументов.

Записи, накопленные в журнале, пронумерованы, и номер служит адресом. По нему разворачивается разбор одного действия: какие каналы тронуты, с каких значений на какие и сколько записей ушло. Отдельная сводка, собираемая при заступлении на смену, показывает действия за последние часы, отказы политики и прогоны процедур.

## Настройка по шагам

Чтение, запись и проверка складываются в цикл. Оператор ведёт настройку словами, а система отрабатывает шаг и показывает, что из этого вышло.

```
Оператор: Проверь орбиту в линаке по x

Sava: -> GetPV("BI-LA1:PK3-fastAvX:Mea" ... "PK7-fastAvX:Mea")
      Макс. отклонение PK5: 207 мкм

Оператор: Сделай коррекцию — используй первые два корректора

Sava: -> GetPV("MG-LA1:CL1:HKICK") -> 0.05
      -> GetPV("MG-LA1:CL2:HKICK") -> 0.0
      -> SetPV("MG-LA1:CL1:HKICK",  0.03)   # было 0.05
      -> SetPV("MG-LA1:CL2:HKICK", -0.02)   # было 0.0
      Коррекция выполнена. Рекомендую проверить результат.

Оператор: Проверь орбиту

Sava: -> GetPV("BI-LA1:PK3-fastAvX:Mea" ... "PK7-fastAvX:Mea")
      Результат: макс. отклонение 77 мкм (↓ в 2.7 раза)
```

Три шага с обратной связью, и отклонение, замеренное на пикапе PK5, упало с 207 до 77 мкм — в 2.7 раза. Прежние уставки корректоров названы в комментариях: оператор видит, откуда и куда сдвинуто, и может вернуть исходное. Такие прогоны гоняются на [цифровом двойнике](./accumulator.md). Двойник говорит на том же протоколе Channel Access и теми же именами каналов, поэтому помощник не отличает его от установки, а цена ошибки при обучении оказывается нулевой. На нём же обкатывается специализация тренера.

Пока коррекция, запущенная оператором, двигает корректоры, машина занята. Замок, объявленный у агента в реестре, заставляет остальных отвечать «оборудование занято», а не отдавать показания, снятые посреди чужой процедуры. Долгая операция шлёт прогресс, и шлюз правит одно уже отправленное сообщение, не засыпая чат лентой статусов. Прогон, оборванный на середине, остаётся в таблице открытым, и заступающая смена видит его в сводке отдельной строкой.

## Когда система заговаривает первой

Разговор начинает не только человек. Сторож, приставленный к списку каналов, следит за порогами и шлёт оператору сообщение, минуя языковую модель: факт, доставляемый мимо неё, доходит и при недоступном провайдере. Объяснение, составленное моделью, приходит вторым сообщением и потерять его не страшно.

Рядом со сторожем работает детектор, замечающий уход внутри порогов — выброс, медленный дрейф или застывшее значение в живом канале. Аномалии, склеенные в инцидент, уходят аналитику, а тот собирает улики с шины и предлагает гипотезу. Предложение, если оно касается машины, превращается в обычное подтверждение, снабжённое числами.

## Как до этого добраться

Интерфейсов три.

- **Telegram-бот** — доступ с любого устройства и в любое время. Текст, фото и голос на входе, текст, графики и голос на выходе; кнопки подтверждения живут здесь же.
- **Веб-интерфейс** — расширенные возможности: длинные диалоги, графики, вставленные прямо в ленту, микрофон.
- **CLI** — встраивание в скрипты и автоматизацию.

Транспортное ядро у всех трёх общее, поэтому разговор, начатый в боте, продолжается в вебе с того же места. Вход в веб и в терминал идёт по одноразовому коду, выданному ботом, и имя оператора в журнале берётся из этого кода, а не из заполненной формы.
