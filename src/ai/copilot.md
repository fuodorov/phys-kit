# GitHub Copilot

Из трёх форм инструментов, разобранных выше, студенту проще всего начать с плагина к редактору. Разберём подробно самый распространённый из них, выбранный не за то, что он лучший, а за то, что он бесплатен даже без подписки — студенту и вовсе достаётся полная версия, — да и ставится он в среду, уже открытую у тебя на экране.

## Что такое GitHub Copilot

**GitHub Copilot** представляет собой плагин к редактору, дописывающий код за тобой. Его сделала компания GitHub вместе с OpenAI, и массовый разработчик познакомился с ним раньше, чем с чат-ботами: первая версия, выпущенная в 2021 году, опередила ChatGPT на полтора года.

> **Проще говоря.** Copilot работает как умное автодополнение, видящее контекст всего файла, а не только строку, набираемую прямо сейчас.

Автодополнением дело давно не ограничивается. Под тем же названием сегодня живут чат по проекту, агентный режим, правящий файлы сам, отдельный агент для командной строки и автоматическое ревью пул-реквестов, то есть все три формы, разобранные в предыдущей главе, а не одна только первая. Начинать всё же стоит с автодополнения: оно требует меньше всего доверия к модели, а к остальному вернёшься, когда научишься читать предложенное.

## Зачем он студентам

Начинаем мы с Copilot по причине, лежащей на поверхности. Попробовать его можно прямо сегодня, не заводя вообще никаких подписок: бесплатный тариф достаётся любому владельцу аккаунта GitHub и ограничен лишь числом автодополнений и запросов в чат за месяц, а студенту, оформившему Student Developer Pack, достаётся полный тариф без этих ограничений.

Пользы от него на этапе учёбы три. Во-первых, он снимает трение с синтаксисом, потому что не нужно каждый раз лезть в документацию за порядком аргументов, вылетающим из головы сразу: по контексту он предложит правильный вызов, а ты запомнишь его, увидев несколько раз. Во-вторых, он неплохо помогает сдвинуться с мёртвой точки, когда смотришь на пустой файл и не знаешь, с чего начать; даже заготовка, набросанная кое-как, даёт, от чего оттолкнуться. В-третьих, его предложения показывают, как принято писать на языке, знакомом тебе плохо. Для физика, раз в год правящего чужой код на C++, это заметное подспорье.

Есть и оговорка, о которой стоит помнить с первого дня. Всё сказанное работает, только если ты читаешь предложенное. Принятое не глядя предложение означает не сэкономленное время, а отложенную отладку.

## Как эффективно использовать Copilot

### Базовые приёмы работы

Единственным рычагом управления здесь остаётся контекст, попадающий модели на вход, то есть открытый файл, соседние вкладки и твои комментарии. Отсюда и приёмы.

1. **Комментируй свои намерения**:
   ```python
   # Напиши функцию для расчёта среднего значения списка
   # Copilot предложит:
   def calculate_average(numbers):
       return sum(numbers) / len(numbers) if numbers else 0
   ```

2. **Создавай шаблоны функций**:
   ```javascript
   function calculateCircleArea(radius) {
     // Copilot предложит:
     return Math.PI * radius * radius;
   }
   ```

3. **Работа с библиотеками**:
   ```python
   import numpy as np
   # Создать массив из 10 случайных чисел от 1 до 100
   # Copilot предложит:
   arr = np.random.randint(1, 101, 10)
   ```

### Продвинутые сценарии

Дальше начинается то, ради чего Copilot обычно и ставят. Он неплохо справляется с однообразной работой вокруг уже написанного кода — тестами и переписыванием кусков, слепленных наспех.

**Генерация тестов**:
```python
# Функция сложения двух чисел
def add(a, b):
    return a + b

# Напиши тесты для этой функции
# Copilot предложит:
def test_add():
    assert add(2, 3) == 5
    assert add(-1, 1) == 0
    assert add(0, 0) == 0
```

**Рефакторинг кода**:
```javascript
// Старый код
function processData(data) {
    let result = [];
    for (let i = 0; i < data.length; i++) {
        if (data[i].active) {
            result.push(data[i].value * 2);
        }
    }
    return result;
}

// Добавь комментарий: "Рефакторинг с использованием map и filter"
// Copilot предложит:
function processData(data) {
    return data
        .filter(item => item.active)
        .map(item => item.value * 2);
}
```

## Примеры для учебных задач

Два примера того, как это выглядит на заданиях, встречающихся на втором курсе. Комментарий, написанный тобой, задаёт задачу, Copilot дописывает остальное; сравни предложенное с тем, что написал бы сам.

### Для курса по алгоритмам
```python
# Реализуй быструю сортировку на Python
# Copilot предложит:
def quicksort(arr):
    if len(arr) <= 1:
        return arr
    pivot = arr[len(arr) // 2]
    left = [x for x in arr if x < pivot]
    middle = [x for x in arr if x == pivot]
    right = [x for x in arr if x > pivot]
    return quicksort(left) + middle + quicksort(right)
```

### Для курса по физике
```python
# Рассчитать траекторию движения тела под углом к горизонту
# Copilot предложит:
def calculate_trajectory(initial_velocity, angle_degrees, times):
    import math
    g = 9.81
    angle_rad = math.radians(angle_degrees)
    vx = initial_velocity * math.cos(angle_rad)
    vy = initial_velocity * math.sin(angle_rad)
    
    trajectory = []
    for t in times:
        x = vx * t
        y = vy * t - 0.5 * g * t**2
        if y < 0:
            break
        trajectory.append((x, y))
    return trajectory
```

## Важные ограничения и предостережения

### Где Copilot ошибается

Ошибки, допускаемые им, бывают трёх сортов, и все три надёжно ловятся чтением.

Самой безобидной оказывается неэффективность. Предложение решает задачу, но лишним проходом или лишней копией, созданной без всякой нужды; на учебных объёмах это незаметно, на рабочих начинает мешать. Дальше идут подходы, успевшие устареть. В обучающих данных старого кода больше, чем свежего, поэтому Copilot охотно предлагает приёмы, от которых в библиотеке уже отказались, и сверяться приходится с документацией, а не с ним.

Опаснее всего третий сорт ошибок, то есть выдумывание. Модель уверенно называет библиотеки, методы и аргументы, не существующие в природе, и выглядит это точно так же, как верный ответ. Здесь и выручает привычка запускать написанное, а не разглядывать его. Метод, придуманный моделью, падает на первом же вызове, а неверная формула молча возвращает правдоподобное число.

### Академическая честность

Правила, принятые на разных курсах, различаются, и выяснять их надо заранее, а не на защите. Общая рамка простая. Copilot служит инструментом обучения, а не способом сдать задание, в котором ты не разобрался. Спроси у преподавателя, что разрешено на его курсе, и в любом случае разбирай сгенерированный код до того, как он попадёт в сдаваемую работу.

## Лучшие практики для студентов

Всё сказанное сводится к пяти рабочим привычкам:

1. **Формулируй задачу точно.** Чем конкретнее комментарий, тем ближе предложение к задуманному тобой
2. **Читай предложение целиком.** Прежде всего смотри на граничные случаи, то есть на пустой список, деление на ноль, отсутствующий файл
3. **Проверяй тестом, а не взглядом.** Короткий тест, написанный на паре значений, отвечает надёжнее самого внимательного чтения
4. **Отдавай ему шаблонное.** Разбор аргументов командной строки, чтение форматов данных, однотипные графики
5. **Смотри не только на первый вариант.** Copilot показывает одно решение из многих, найденных им, и не всегда лучшее

## Заключение

Copilot экономит время на том, что ты и так умеешь, то есть на шаблонном коде, на синтаксисе плохо знакомого языка, на первой заготовке, появляющейся в пустом файле. Понимания он не добавляет, оно остаётся твоей работой, и от того, делаешь ты её или нет, зависит, окажется он помощником или костылём.

**Главный принцип таков.** Пользуйся Copilot, чтобы **углубить понимание**, а не чтобы **обойтись без него**.
