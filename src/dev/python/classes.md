# Классы

Класс связывает данные с операциями, определёнными над ними, и вместо разрозненных переменных и функций, обрабатывающих их, получается один объект, отвечающий за своё состояние. От Java и C++ Python отличается тем, что не прячет механику: ссылка на экземпляр передаётся методу явным первым аргументом `self`, а не появляется в теле сама собой.

ООП в Python не обязательно. Модуль, набранный из десятка функций, — нормальная программа, и заворачивать её в класс только ради класса не нужно. Классы берут тогда, когда у данных появляется состояние, которое надо держать согласованным, или когда одну и ту же операцию нужно выполнять по-разному для объектов разного вида, обрабатываемых единым кодом.

## Базовые понятия

### Определение класса

Метод `__init__` вызывается сразу после создания объекта и задаёт начальное состояние; всё, записанное в `self`, становится атрибутом конкретного экземпляра, которым и пользуются остальные методы.

```python
class Counter:
    """I count. That is all."""
    
    def __init__(self, initial=0):  # конструктор
        self.value = initial        # запись атрибута

    def increment(self):
        self.value += 1

    def get(self):
        return self.value          # чтение атрибута

# Использование
c = Counter(42)
c.increment()
print(c.get())  # 43
```

Название «конструктор», прижившееся за `__init__`, строго говоря неверно, поскольку объект к этому моменту уже создан. Создаёт его метод `__new__`, а `__init__` только заполняет заготовку, полученную от него. Разница проявляется при наследовании от неизменяемого типа вроде `int` или `tuple`, у которого менять уже нечего, и вся работа переносится в `__new__`.

### Специфика Python

Первым аргументом любого метода идёт `self`, то есть экземпляр, на котором метод вызвали, причём вписывать его приходится вручную, по правилу «явное лучше неявного».

Модификаторов доступа вроде `private` и `protected` в Python нет, вместо них действует соглашение об именовании.

- `public_attribute` составляет часть публичного интерфейса, им можно пользоваться;
- `_internal_attribute` внутренний, снаружи его не трогают;
- `__private_attribute` означает то же самое, но с дополнительной защитой от случайного переопределения, сделанного в подклассе.

Только за двойным подчёркиванием стоит механизм, встроенный в язык. Интерпретатор переписывает имя, помеченное так, добавляя к нему имя класса, отчего `__private` внутри класса `Counter` превращается в `_Counter__private`. Придумано это против коллизий, а не ради сокрытия данных, так что базовый класс и подкласс, заведя по атрибуту `__cache`, не столкнутся. А добраться до «приватного» атрибута всё равно можно, написав полное имя.

## Атрибуты классов и экземпляров

Атрибуты в Python бывают двух сортов, и путаница между ними даёт упорные баги.

### Атрибуты экземпляра

Атрибут экземпляра появляется от присваивания, сделанного к `self`, и принадлежит только этому объекту. Заводить его не обязательно в `__init__`, потому что присвоить атрибут можно и снаружи, объекту, уже созданному.

```python
class Noop:
    def __init__(self):
        self.some_attribute = 42

noop = Noop()
noop.other_attribute = 100500  # динамическое добавление
```

Свобода эта следует из того, что атрибуты хранятся в обычном словаре, и у неё есть оборотная сторона: опечатка в имени не вызовет ошибки. Строка `noop.som_attribute = 0` молча заведёт новый атрибут, а старый останется прежним.

### Атрибуты класса

Атрибут, объявленный в теле класса, принадлежит самому классу и **один на всех** его экземпляров. Годится это для общих вещей: настроек, констант, реестра созданных объектов.

```python
class Counter:
    all_counters = []  # атрибут класса
    
    def __init__(self, initial=0):
        Counter.all_counters.append(self)
        self.value = initial

# Также можно добавлять атрибуты после определения
Counter.some_other_attribute = 42
```

Ловушка та же, что с изменяемыми аргументами по умолчанию: список `all_counters` создаётся один раз, при чтении определения класса. Задумай ты его как список, заведённый у каждого счётчика отдельно, все экземпляры делили бы один. Здесь общий список нужен, но, объявляя изменяемый атрибут класса, проверяй, должен ли он быть общим.

### Словарь атрибутов

Все атрибуты экземпляра лежат в обычном словаре `__dict__`, благодаря которому и работает динамическое добавление. В него можно заглянуть, посмотреть на поля, заведённые у объекта, и писать напрямую.

```python
noop = Noop()
noop.some_attribute = 42
print(noop.__dict__)  # {'some_attribute': 42}
print(vars(noop))     # альтернативный способ

# Динамическое управление атрибутами
noop.__dict__["dynamic_attr"] = "value"
```

Встроенная `vars()` с аргументом отдаёт `__dict__` объекта, а без аргументов возвращает словарь текущего локального пространства имён. Прямая запись в `__dict__` нужна редко, но пригодится при имени атрибута, вычисляемом на ходу.

### `__slots__` для оптимизации

За гибкость приходится платить памятью, так как словарь, заведённый у каждого экземпляра, на объекте с двумя полями весит больше самих полей. Если объектов миллионы, по одному на событие, записанное в эксперименте, плата становится ощутимой.

`__slots__` фиксирует набор допустимых атрибутов заранее, благодаря чему интерпретатор обходится без словаря и раскладывает значения по ячейкам, отведённым при создании объекта.

```python
class Noop:
    __slots__ = ["some_attribute"]  # фиксирует набор атрибутов
    
    def __init__(self):
        self.some_attribute = 42

# Экономит память, но запрещает добавление новых атрибутов
```

На объекте с парой полей это экономит около 40 % памяти, 96 байт на экземпляр без слотов против 56 со слотами. Скорость доступа не меняется: замер, приведённый в главе про оптимизацию, показывает, что разница уходит в шум. Взамен теряется динамика: добавить атрибут, отсутствующий в списке, не получится, будет `AttributeError`, и перестают работать слабые ссылки, если `__weakref__` не вписан в слоты явно. Начинать с `__slots__` не надо; добавляй его, когда профилировщик покажет, что память уходит сюда.

## Методы

### Связанные и несвязанные методы

Метод — это функция, лежащая в атрибуте класса, и достать её можно двумя путями. Через класс получается обычная функция, требующая экземпляр, переданный руками. Через экземпляр получается **связанный** метод, в котором объект уже подставлен в `self`, и передавать его повторно не нужно.

```python
class SomeClass:
    def do_something(self):
        print("Doing something.")

# Несвязанный метод
method = SomeClass.do_something
instance = SomeClass()
method(instance)  # нужно явно передать экземпляр

# Связанный метод
bound_method = instance.do_something
bound_method()  # self уже привязан
```

Связанный метод представляет собой полноценный объект: его кладут в переменную, передают в `map` или регистрируют как обработчик события, а ссылку на свой экземпляр он носит с собой. В Python 2 обращение через класс давало особый тип, проверявший тип первого аргумента и не пропускавший посторонние объекты; в Python 3 это обычная функция.

## Свойства (Properties)

Публичный атрибут иногда нужно защитить проверкой или вычислять на лету. В языках со строгой инкапсуляцией на этот случай заранее пишут геттеры и сеттеры для всех полей. В Python атрибут остаётся атрибутом, а когда понадобится, за ним прячут методы, не меняя код, пользующийся им.

Делает это декоратор `@property`: метод, поставленный под ним, вызывается при чтении, метод под `@имя.setter` при записи, метод под `@имя.deleter` при удалении. Снаружи всё выглядит как обычное присваивание.

```python
class BigDataModel:
    def __init__(self):
        self._params = []
    
    @property
    def params(self):
        return self._params
    
    @params.setter
    def params(self, new_params):
        assert all(p > 0 for p in new_params)
        self._params = new_params
    
    @params.deleter
    def params(self):
        del self._params

model = BigDataModel()
model.params = [0.1, 0.5, 0.4]
print(model.params)  # [0.1, 0.5, 0.4]
```

Присваивание `model.params = [...]` выглядит как запись в обычное поле, но проходит через `assert` в сеттере. Интерфейс не меняется, а поведение за ним — сколько угодно. Внутри свойства устроены на дескрипторах, разобранных в конце главы.

## Наследование

### Базовое наследование

Подкласс получает всё, объявленное у родителя, и добавляет своё. Если метода нет у подкласса, интерпретатор поднимается по цепочке наследования и ищет его выше. `OtherCounter` не определяет `__init__`, поэтому при создании работает родительский.

```python
class Counter:
    def __init__(self, initial=0):
        self.value = initial

class OtherCounter(Counter):
    def get(self):
        return self.value

oc = OtherCounter()  # вызывает Counter.__init__
print(oc.get())      # вызывает OtherCounter.get
```

Родителей, в отличие от многих языков, может быть несколько, и чем сложнее иерархия, тем труднее сказать, чей метод, найденный по цепочке, вызовется.

### Перегрузка методов и `super()`

Чаще подкласс не заменяет метод родителя целиком, а надстраивает над ним своё и передаёт управление наверх, а ссылку на реализацию, унаследованную от родителя, даёт `super()`.

```python
class Counter:
    all_counters = []
    
    def __init__(self, initial=0):
        self.__class__.all_counters.append(self)
        self.value = initial
    
    def increment(self):
        self.value += 1
    
    def get(self):
        return self.value

class OtherCounter(Counter):
    def __init__(self, initial=0):
        self.initial = initial
        super().__init__(initial)  # вызов родительского конструктора
```

Писать `Counter.__init__(self, initial)` вместо `super()` — распространённая ошибка, и разница вылезет при множественном наследовании. `super()` идёт не к родителю, а к следующему классу в порядке разрешения методов, зависящем от того, как класс использовали дальше. Имя родителя, вписанное явно, эту цепочку рвёт.

### Множественное наследование

Порядок, в котором интерпретатор перебирает классы в поисках метода, называется MRO, то есть method resolution order, и посчитанный список видно у любого класса.

```python
class A:
    def f(self):
        print("A.f")

class B:
    def f(self):
        print("B.f")

class C(A, B):
    pass

print(C.mro())  # порядок разрешения методов
C().f()         # A.f (согласно MRO)
```

Здесь `f` находится в `A`, потому что `A` стоит первым в списке родителей, перечисленных в скобках. Порядок, выстраиваемый тут, считает алгоритм C3, заимствованный из языка Dylan, и он даёт три гарантии. Подкласс всегда идёт раньше своих родителей; порядок, в котором родители перечислены, сохраняется; каждый класс иерархии встречается в списке единожды. Если требования противоречат друг другу, Python откажется создавать класс.

### Классы-примеси

Примесью (mixin) называют класс, не задуманный для самостоятельного использования и не описывающий сущность, а только добавляющий к чужому поведению одну черту, будь то блокировка, журналирование или кеширование. Ниже примесь оборачивает операции счётчика в блокировку, захваченную на время вызова.

```python
import threading

class ThreadSafeMixin:
    def __init__(self, *args, **kwargs):
        self._lock = threading.Lock()
        super().__init__(*args, **kwargs)
    
    def get_lock(self):
        return self._lock
    
    def increment(self):
        with self.get_lock():
            super().increment()
    
    def get(self):
        with self.get_lock():
            return super().get()

class ThreadSafeCounter(ThreadSafeMixin, Counter):
    pass
```

Работает всё это благодаря `super()` и порядку разрешения методов. Примесь стоит **перед** `Counter` в списке родителей, поэтому её `increment` перехватывает вызов первым, а `super().increment()`, стоящий внутри, уходит дальше по цепочке, в настоящий счётчик. `ThreadSafeMixin` не наследуется от `Counter` и ничего о нём не знает: следующий класс в MRO определяется в момент, когда собирают `ThreadSafeCounter`. Так же устроена половина Django.

## Декораторы классов

Декоратор применяется не только к функциям: класс тоже объект, и его можно пропустить через функцию, возвращающую что-то другое. Классическим примером служит синглтон, где класс подменяют функцией, создающей экземпляр при первом вызове и дальше отдающей тот же самый.

```python
import functools

def singleton(cls):
    instance = None
    
    @functools.wraps(cls)
    def inner(*args, **kwargs):
        nonlocal instance
        if instance is None:
            instance = cls(*args, **kwargs)
        return instance
    
    return inner

@singleton
class Noop:
    "I do nothing at all."

print(id(Noop()) == id(Noop()))  # True
```

Декораторы классов появились в Python 3.0 и потеснили метаклассы: многое, ради чего раньше писали метакласс, теперь делают одной функцией. Самый известный пример — `@dataclass`, дописывающий классу `__init__`, `__repr__` и `__eq__` по полям, объявленным в теле.

## Магические методы

Магическими (или дандер-) методами называют методы, чьи имена окружены двойными подчёркиваниями. Напрямую их не вызывают, поскольку за каждым стоит синтаксическая конструкция или встроенная функция. Определив нужный метод, ты учишь свой объект вести себя как встроенный, то есть складываться, сравниваться, печататься, попадать в множество.

### Управление атрибутами

Первая группа перехватывает работу с атрибутами. `__getattr__` вызывается **только тогда, когда атрибут не нашёлся** обычным путём, и в нём подставляют значение вместо `AttributeError`. `__setattr__` и `__delattr__`, наоборот, перехватывают вообще любую запись и любое удаление.

```python
class Noop:
    def __getattr__(self, name):
        # Вызывается при доступе к несуществующему атрибуту
        return f"Attribute {name} doesn't exist"
    
    def __setattr__(self, name, value):
        # Вызывается при установке любого атрибута
        super().__setattr__(name, value)
    
    def __delattr__(self, name):
        # Вызывается при удалении атрибута
        super().__delattr__(name)

noop = Noop()
print(noop.non_existent)  # "Attribute non_existent doesn't exist"
```

Обращение к `super()` внутри `__setattr__` обязательно: `self.name = value` вызовет метод рекурсивно. По этой же причине не трогай `__getattribute__`, перехватывающий доступ ко **всем** атрибутам, а не только к пропавшим.

### Операторы сравнения

Вторая группа отвечает за сравнение, и методов в ней шесть, но писать все шесть незачем: декоратор `@functools.total_ordering` достроит остальные по `__eq__` и любому одному из методов, задающих упорядочивание.

```python
import functools

@functools.total_ordering
class Counter:
    def __init__(self, value):
        self.value = value
    
    def __eq__(self, other):
        return self.value == other.value
    
    def __lt__(self, other):
        return self.value < other.value

c1, c2 = Counter(1), Counter(2)
print(c1 < c2)   # True
print(c1 >= c2)  # False (автоматически из __lt__ и __eq__)
```

Определив `__eq__`, ты отключаешь хеширование: объект не попадёт ни в множество, ни в ключи словаря. Причина та же, что у изменяемых коллекций: равные объекты обязаны иметь равные хеши, а угадывать их Python не берётся. Если объект должен оставаться хешируемым, напиши `__hash__` явно.

### Строковое представление

Третья группа отвечает за текстовое представление. `__repr__` пишут для программиста: он должен быть однозначным и в идеале выглядеть как выражение, воссоздающее объект. `__str__` пишут для человека, смотрящего на вывод программы. Если `__str__` не определён, Python возьмёт `__repr__`, поэтому начинают с него.

```python
class Counter:
    def __init__(self, initial=0):
        self.value = initial
    
    def __repr__(self):
        return f"Counter({self.value})"
    
    def __str__(self):
        return f"Counted to {self.value}"
    
    def __format__(self, format_spec):
        return self.value.__format__(format_spec)

c = Counter(42)
print(repr(c))           # Counter(42)
print(str(c))            # Counted to 42
print(f"{c:b}")          # 101010 (бинарное представление)
```

Третий метод, `__format__`, отвечает за подстановку в f-строку со спецификатором, а здесь он передаёт полученный спецификатор дальше в целое число, поэтому `{c:b}` печатает значение счётчика в двоичном виде.

Пиши `__repr__` у любого класса, живущего дольше пары строк, иначе при отладке объекты печатаются как `<__main__.Counter object at 0x7f3a…>`.

### Другие полезные магические методы

`__call__` делает экземпляр вызываемым, и на этом строят декораторы, написанные классами, и объекты, хранящие настройки между вызовами. `__bool__` задаёт, что объект значит в условии `if`; без него Python спрашивает `__len__`, и объект нулевой длины оказывается ложным, а объект без обоих методов истинен всегда. `__hash__` определяет, как объект попадает в множества и словари.

```python
class Identity:
    def __call__(self, x):
        # Позволяет вызывать экземпляры как функции
        return x
    
    def __bool__(self):
        # Определяет поведение в булевом контексте
        return True
    
    def __hash__(self):
        # Используется для хеширования в словарях и множествах
        return hash(id(self))

identity = Identity()
print(identity(42))  # 42
```

`__call__` стирает границу между функцией и объектом: вызов `identity(42)` выглядит как обычный, хотя слева стоит экземпляр класса. Поэтому всюду, где документация просит передать функцию, годится любой объект с `__call__`.

## Дескрипторы

Свойство решает задачу для одного атрибута одного класса, а проверка на неотрицательность нужна десяткам полей в разных классах. Дескриптор выносит логику доступа в отдельный класс, откуда её можно переиспользовать.

### Базовый дескриптор

Дескриптор — это класс с определёнными `__get__`, `__set__` или `__delete__`. Экземпляр такого класса, положенный в **атрибут класса**, с этого момента перехватывает любое обращение к атрибуту.

```python
class NonNegative:
    def __get__(self, instance, owner):
        # magically_get_value
        pass
    
    def __set__(self, instance, value):
        assert value >= 0, "non-negative value required"
        # magically_set_value
    
    def __delete__(self, instance):
        # magically_delete_value
        pass

class VerySafe:
    x = NonNegative()
    y = NonNegative()

very_safe = VerySafe()
very_safe.x = 42      # OK
very_safe.x = -42     # AssertionError
```

Проверка написана один раз, полей, защищённых ею, два, и добавить третье стоит одной строки.

Через дескрипторы в Python реализовано почти всё, связанное с атрибутами: и `@property`, и `@staticmethod`, и `@classmethod`, и сама привязка методов к экземпляру. Знать протокол напрямую нужно нечасто, но он объясняет, почему функция, лежащая в классе, при обращении через экземпляр оказывается связанным методом.

### Хранение данных в дескрипторах

Держать значение в самом дескрипторе нельзя: он один на весь класс, а экземпляров много, и значения, записанные ими, затирали бы друг друга; правильное место — словарь самого экземпляра.

```python
class Proxy:
    def __init__(self, label):
        self.label = label
    
    def __get__(self, instance, owner):
        return instance.__dict__[self.label]
    
    def __set__(self, instance, value):
        instance.__dict__[self.label] = value
    
    def __delete__(self, instance):
        del instance.__dict__[self.label]

class Something:
    attr = Proxy("attr")

some = Something()
some.attr = 42
print(some.attr)  # 42
```

У каждого экземпляра значение своё, и живёт оно столько же, сколько сам экземпляр. Второй вариант, общий словарь «экземпляр → значение», заведённый внутри дескриптора, хуже по двум причинам: он требует, чтобы объекты были хешируемыми, и держит на них ссылки, не давая сборщику мусора их убрать.

Имя поля приходится дублировать в `Proxy("attr")`; с Python 3.6 от этого избавляет метод `__set_name__`, вызываемый интерпретатором при создании класса и сообщающий дескриптору имя, под которым тот записан.

### Встроенные дескрипторы

Три реализации ниже сокращены, но верно передают устройство, зашитое в интерпретатор.

```python
# @property реализован через дескрипторы
class property:
    def __init__(self, get=None, set=None, delete=None):
        self._get = get
        self._set = set
        self._delete = delete
    
    def __get__(self, instance, owner):
        if self._get is None:
            raise AttributeError("unreadable attribute")
        return self._get(instance)

# @staticmethod и @classmethod тоже используют дескрипторы
class staticmethod:
    def __init__(self, method):
        self.__method = method
    
    def __get__(self, instance, owner):
        return self.__method

class classmethod:
    def __init__(self, method):
        self.__method = method
    
    def __get__(self, instance, owner):
        if owner is None:
            owner = type(instance)
        return self.__method.__get__(owner, type(owner))
```

Вся разница между `@staticmethod` и `@classmethod` умещается в их `__get__`. Статический метод отдаёт исходную функцию без привязки, поэтому и `self` в нём нет. Метод класса привязывает функцию к классу, и первым аргументом приходит сам класс. Так же, только к экземпляру, привязываются обычные методы.

## Метаклассы

Раз класс является объектом, у него тоже есть тип. Типом обычного класса служит `type`, а метаклассом называют просто класс, унаследованный от `type`, экземплярами которого оказываются другие классы. Если обычный класс описывает, как устроены его объекты, то метакласс описывает, как устроены сами классы.

Нужны они редко: почти всё, ради чего раньше писали метаклассы, сегодня делается декоратором, навешенным на класс, или методом `__init_subclass__`. Но на метаклассах построены ORM и системы валидации данных, где поля, объявленные в классе, описываются декларативно.

### Базовый метакласс

Метакласс перехватывает создание класса, а его метод `__new__` получает всё, из чего класс будет собран, то есть имя, кортеж родителей и словарь, набранный из тела класса, и может поменять полученное до создания класса.

```python
from collections import OrderedDict

class Meta(type):
    def __new__(metacls, name, bases, clsdict):
        print(f"Creating class {name}")
        cls = super().__new__(metacls, name, bases, clsdict)
        return cls
    
    @classmethod
    def __prepare__(metacls, name, bases):
        # Может вернуть нестандартный mapping для clsdict
        return OrderedDict()

class Something(metaclass=Meta):
    attr = "foo"
    other_attr = "bar"
```

Второй метод, `__prepare__`, выбирает, в чём копить тело класса, пока оно читается. Возвращённый им словарь и попадёт потом в `clsdict`, а значит, подсунув сюда свой тип отображения, можно запомнить порядок объявления атрибутов или проверять на месте каждое сделанное присваивание. Так и работают ORM, где порядок полей определяет порядок колонок, созданных в таблице. Начиная с версии 3.7 тело класса и без `__prepare__` копится в обычном `dict`, сохраняющем порядок вставки, так что `OrderedDict` здесь нужен не ради порядка, а ради `move_to_end` и прочего, чего у простого словаря нет.

### Создание классов через `type()`

Оператор `class` — удобная запись вызова `type` с тремя аргументами: именем, родителями и словарём атрибутов.

```python
# Эквивалентно class Something: attr = 42
name, bases, attrs = "Something", (), {"attr": 42}
Something = type(name, bases, attrs)

some = Something()
print(some.attr)  # 42
```

## Модуль abc для абстрактных базовых классов

Абстрактный базовый класс описывает интерфейс, не реализуя его, и перечисляет методы, обязательные для наследника. Пока хоть один из них не реализован, класс считается абстрактным, и создать его экземпляр не выйдет, а ошибка возникнет сразу, а не при первом обращении к недостающему методу.

```python
import abc

class Iterable(metaclass=abc.ABCMeta):
    @abc.abstractmethod
    def __iter__(self):
        pass

class Something(Iterable):
    pass

# Something()  # TypeError: Can't instantiate abstract class
```

Отдельной конструкции `interface`, как в Java, в Python нет: интерфейсы описываются обычными классами с заданным метаклассом `ABCMeta`. Проще всего наследоваться от готового `abc.ABC`, делающего то же самое.

## Модуль collections.abc

Абстрактные классы для самих коллекций уже написаны и лежат в `collections.abc`, и это те же `Container`, `Iterable`, `Sequence` и `Mapping`, разобранные в главе про коллекции. Пользы от наследования две: интерпретатор сначала проверит, что реализовано всё обязательное, а потом сам добавит остальное. Реализовав у `MutableMapping` пять методов, ты получишь готовые `get`, `pop`, `setdefault`, `update`, `items`, `keys` и `values`.

```python
from collections import deque
from collections.abc import MutableMapping

class MemorizingDict(MutableMapping):
    def __init__(self, *args, **kwargs):
        self._data = dict(*args, **kwargs)
        self._history = deque(maxlen=10)
    
    def __getitem__(self, key):
        return self._data[key]
    
    def __setitem__(self, key, value):
        self._history.append(key)
        self._data[key] = value
    
    def __delitem__(self, key):
        del self._data[key]
    
    def __iter__(self):
        return iter(self._data)
    
    def __len__(self):
        return len(self._data)
    
    def get_history(self):
        return self._history
```

Написано пять обязательных методов и один свой, а на выходе получается полноценный словарь, помнящий десять последних записанных ключей. Он пройдёт `isinstance(d, MutableMapping)` и будет принят любой библиотекой, ждущей отображение.

## Заключение

Большая часть этого инструментария тебе не понадобится: метаклассы за студенческую практику, скорее всего, не встретятся ни разу, дескрипторы попадутся от силы однажды. Разбирают их потому, что почти всё, кажущееся в Python магией, оказывается одним из этих механизмов.

В повседневной работе хватает малого:

- Класс нужен там, где есть состояние, которое надо держать согласованным. Если состояния нет, хватит функции.
- Атрибут пусть остаётся атрибутом; свойство добавляют тогда, когда за ним понадобилась логика.
- `__repr__` пиши сразу.
- В переопределённых методах вызывай родителя через `super()`, а не по имени класса.
- Прежде чем строить иерархию наследования, подумай, не решается ли задача композицией: объект, **содержащий** другой объект, почти всегда проще объекта, унаследованного от него.

Язык одинаково принимает и модуль из десяти функций, и иерархию классов; выбирай по задаче, а не по привычке, накопленной в других языках.
