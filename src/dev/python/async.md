# Итераторы, генераторы и корутины

Эта глава посвящена трём родственным механизмам языка, связанным одной идеей — **не вычислять всё сразу**. Итератор выдаёт элементы по одному, генератор умеет приостанавливать выполнение функции и возвращаться в неё, а корутина вдобавок умеет принимать значения, присланные снаружи.

Механизмы полезны сами по себе, поскольку позволяют обрабатывать файлы, не вмещаемые в память, и описывать бесконечные последовательности. Но главное в том, что на генераторах построена вся асинхронность Python. Разобравшись здесь, ты без труда поймёшь `asyncio` в главе, посвящённой [асинхронности](../../perf/async.md).


## Итераторы

Итераторы относятся к фундаментальным концепциям Python, применяемым ежедневно, часто без раздумий о механике, стоящей за ними. Любая коллекция, встроенная в язык (списки, словари, множества, строки, файлы), итерируема.

Формально итератор — это объект с методом `__next__`, который на каждом вызове отдаёт следующий элемент, а когда элементы кончились, возбуждает `StopIteration`. Отдельно существует *итерируемый* объект, обладающий методом `__iter__`, возвращающим итератор. Разделение, проведённое между ними, не формальность: список итерируем, но не является итератором, поэтому по нему можно пройти дважды, а по итератору лишь один раз.

Соберём свой аналог `range`, чтобы увидеть обе роли явно. Контейнер `Range` умеет только выдать итератор, а сам обход делает `RangeIterator`.

```python
class Range:
    def __init__(self, stop_value: int):
        self.stop_value = stop_value - 1

    def __iter__(self):
        return RangeIterator(self)

class RangeIterator:
    def __init__(self, container):
        self.container = container
        self.current = -1          # состояние обхода живёт здесь

    def __iter__(self):
        return self                # итератор обязан быть итерируемым

    def __next__(self):
        if self.current < self.container.stop_value:
            self.current += 1
            return self.current
        raise StopIteration
```

Существенно, где лежит `current`: он в итераторе, а не в контейнере, и
поэтому каждый новый `for` начинает счёт заново, а по одному `Range(5)`, созданному однажды, можно
пройти сколько угодно раз. Положи счётчик в контейнер, и второй проход окажется
пустым, хотя код, написанный тобой, будет выглядеть почти так же. Метод `__iter__` у самого
итератора тоже не формальность: без него объект не итерируем, и `for`, запущенный по нему,
не пойдёт.

Чаще, впрочем, обе роли совмещают в одном классе, где `__iter__` возвращает `self`, и кода тогда меньше, но второй проход по объекту, устроенному так, начнётся там, где закончился первый.

```python
class Range2:
    def __init__(self, stop_value: int):
        self.current = -1
        self.stop_value = stop_value - 1
    
    def __iter__(self):
        return self
    
    def __next__(self):
        if self.current < self.stop_value:
            self.current += 1
            return self.current
        raise StopIteration
```

Теперь видно, что делает обычный `for`, который берёт итератор через `iter`, дёргает `next` в цикле и ловит `StopIteration`, чтобы остановиться. Вот что разворачивается за привычной строчкой, набранной в одну строку.

```python
iterable = Range2(5)
iterator = iter(iterable)

while True:
    try:
        value = next(iterator)
        print(value)
    except StopIteration:
        break
```

## Генераторы

Генераторы работают на принципе запоминания контекста, сохранённого ключевым словом `yield`.

Писать два класса ради простого перебора утомительно, и в языке есть короткий путь. Стоит поставить в функцию `yield`, и она перестаёт быть обычной: при вызове её тело не выполняется вовсе, а вместо него возвращается генератор. Тело, замороженное до поры, оживает при `next`, доходит до ближайшего `yield`, отдаёт значение и **замирает**, сохранив все локальные переменные и место, выбранное для остановки.

В примере, приведённом ниже, это видно по трём вызовам, из которых первые два отдают значения, а третий натыкается на `return` и возбуждает `StopIteration`, положив в неё возвращённое значение.

```python
def simple_generator():
    yield 1
    yield 2
    return 3

gen = simple_generator()
print(next(gen))  # 1
print(next(gen))  # 2
print(next(gen))  # StopIteration: 3
```

Есть и совсем краткая форма — генераторное выражение; от спискового включения его отличают круглые скобки, поставленные вместо квадратных, и разница принципиальна. Список из ста тысяч элементов, построенный целиком, займёт память, а генератор не вычислит ни одного элемента, пока его не попросят. В памяти это 800 килобайт против 200 байт.

```python
gen_exp = (x for x in range(100000))
print(gen_exp)  # <generator object <genexpr> at 0x...>
```

Обе выгоды, обещанные в начале главы, видны на паре примеров. Журнал захода, писавшийся всю смену, в память целиком не влезает, но построчно читается так же просто, как список: файл сам по себе итератор, а генератор, надетый сверху, отбрасывает лишнее и отдаёт наружу по одному разобранному событию, держа в памяти только текущую строку.

```python
def read_events(path):
    """Отдаёт события журнала по одному, не читая файл целиком."""
    with open(path) as f:
        for line in f:
            if not line.strip() or line.startswith('#'):
                continue           # пустые строки и комментарии пропускаем
            t, channel, value = line.split()
            yield float(t), channel, float(value)

for t, channel, value in read_events('run042.log'):
    if channel == 'BPM01':
        print(t, value)
```

Обратный случай — последовательность, у которой конца нет вовсе. Генератор отсчётов не знает, сколько их спросят, и считает, пока спрашивают, а границу ставит тот, кто читает: `itertools.islice` берёт первые сколько-то значений и отпускает генератор, так и не доведя его до несуществующего конца.

```python
import itertools

def clock(dt):
    """Бесконечная последовательность моментов времени с шагом dt."""
    t = 0.0
    while True:
        yield t
        t += dt

for t in itertools.islice(clock(0.02), 5):
    print(round(t, 3))  # 0.0, 0.02, 0.04, 0.06, 0.08 — по одному в строке
```

Когда генератор просто пересказывает элементы, взятые из другого источника, цикл с `yield` записывают короче через `yield from`. Это не только сахар: конструкция пробрасывает внутрь, до вложенного генератора, всё, что посылают через `send` и `throw`, а наружу отдаёт его `return`, и это понадобится, как только генераторы начнут вкладываться друг в друга.

```python
numbers = [1, 2, 3]

# Стандартный подход
def func():
    for item in numbers:
        yield item

# Упрощенный подход
def func():
    yield from numbers
```

## Корутины

Корутины служат основными строительными блоками асинхронного программирования. Выросшие из генераторов, они решают задачу не параллельного счёта, а ожидания, позволяя одному потоку заняться другим делом, пока текущая задача ждёт ответа от сети или диска.

Корутина переворачивает картину, нарисованную выше: генератор только отдаёт значения наружу, а корутина умеет и **принимать** их. Выражение `deposit = (yield)` приостанавливает функцию и ждёт, пока снаружи вызовут `send`. Выходит диалог с функцией, сохраняющей между вопросами своё состояние.

Разберём на счёте сложных процентов. Коэффициент роста, посчитанный один раз при создании корутины, дальше не меняется, а суммы вклада в неё можно слать бесконечно.

```python
import math
from collections.abc import Generator

def cash_return_coro(percent: float,
                     years: int) -> Generator[float | None, float, None]:
    value = math.pow(1 + percent / 100, years)
    while True:
        try:
            deposit = (yield)
            yield round(deposit * value, 2)
        except GeneratorExit:
            print('Выход из корутины')
            raise

# Использование
coro = cash_return_coro(5, 5)
next(coro)
values = [1000, 2000, 5000, 10000, 100000]
for item in values:
    print(coro.send(item))
    next(coro)
coro.close()
```

За один оборот цикла корутина замирает дважды: сначала на `yield`, принимающем вклад, потом на `yield`, отдающем результат. Поэтому `send` возвращает посчитанное число, а следующий за ним `next` доводит корутину до очередного приёма.

## Что дальше

Мы разобрали механику. Итератор отдаёт элементы по одному, генератор приостанавливает функцию на `yield` и продолжает с места, запомненного при остановке, а корутина умеет ещё и принимать значения через `send()`.

На фундаменте, заложенном здесь, и построена асинхронность в Python. Цикл событий представляет собой планировщик, который переключается между приостановленными генераторами и отдаёт процессорное время тому, кто готов работать, пока остальные ждут ответа от сети или диска. Как это устроено внутри и как этим пользоваться через `asyncio`, разбирается в главе про асинхронность, помещённой в раздел «Ускоряем код».
