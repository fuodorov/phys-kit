# Итераторы, генераторы и корутины

Три родственных механизма языка связаны одной идеей — **не вычислять всё сразу**. Итератор выдаёт элементы по одному, генератор умеет приостанавливать выполнение функции и возвращаться в неё, а корутина вдобавок умеет принимать значения, присланные снаружи.

Они позволяют обрабатывать файлы, не вмещаемые в память, и описывать бесконечные последовательности, а на генераторах построена вся асинхронность Python — `asyncio` разбирается в главе, посвящённой [асинхронности](../../perf/async.md).


## Итераторы

Любая коллекция, встроенная в язык (списки, словари, множества, строки, файлы), итерируема.

Итератор — это объект с методом `__next__`, который на каждом вызове отдаёт следующий элемент, а когда элементы кончились, возбуждает `StopIteration`. *Итерируемый* объект обладает методом `__iter__`, возвращающим итератор. Список итерируем, но не итератор, поэтому по нему можно пройти дважды, а по итератору лишь один раз.

Соберём свой аналог `range`, чтобы увидеть обе роли явно. Контейнер `Range` умеет только выдать итератор, а сам обход делает `RangeIterator`.

```python
class Range:
    def __init__(self, stop_value: int):
        self.stop_value = stop_value - 1

    def __iter__(self):
        return RangeIterator(self)

class RangeIterator:
    def __init__(self, container):
        self.container = container
        self.current = -1          # состояние обхода живёт здесь

    def __iter__(self):
        return self                # итератор обязан быть итерируемым

    def __next__(self):
        if self.current < self.container.stop_value:
            self.current += 1
            return self.current
        raise StopIteration
```

`current` лежит в итераторе, а не в контейнере,
поэтому каждый новый `for` начинает счёт заново, а по одному `Range(5)` можно
пройти сколько угодно раз. Положи счётчик в контейнер, и второй проход окажется
пустым. Без метода `__iter__` у самого
итератора объект не итерируем, и `for` по нему не пойдёт.

Чаще обе роли совмещают в одном классе, где `__iter__` возвращает `self`: кода меньше, но второй проход начнётся там, где закончился первый.

```python
class Range2:
    def __init__(self, stop_value: int):
        self.current = -1
        self.stop_value = stop_value - 1
    
    def __iter__(self):
        return self
    
    def __next__(self):
        if self.current < self.stop_value:
            self.current += 1
            return self.current
        raise StopIteration
```

Обычный `for` берёт итератор через `iter`, дёргает `next` в цикле и ловит `StopIteration`, чтобы остановиться.

```python
iterable = Range2(5)
iterator = iter(iterable)

while True:
    try:
        value = next(iterator)
        print(value)
    except StopIteration:
        break
```

## Генераторы

Генераторы работают на принципе запоминания контекста, сохранённого ключевым словом `yield`.

Писать два класса ради простого перебора утомительно. Функция с `yield` при вызове не выполняет тело, а возвращает генератор. Тело оживает при `next`, доходит до ближайшего `yield`, отдаёт значение и **замирает**, сохранив все локальные переменные и место остановки.

Ниже первые два вызова отдают значения, а третий натыкается на `return` и возбуждает `StopIteration`, положив в неё возвращённое значение.

```python
def simple_generator():
    yield 1
    yield 2
    return 3

gen = simple_generator()
print(next(gen))  # 1
print(next(gen))  # 2
print(next(gen))  # StopIteration: 3
```

Есть и краткая форма — генераторное выражение; от спискового включения его отличают круглые скобки вместо квадратных. Список из ста тысяч элементов займёт память целиком, а генератор не вычислит ни одного элемента, пока его не попросят: 800 килобайт против 200 байт.

```python
gen_exp = (x for x in range(100000))
print(gen_exp)  # <generator object <genexpr> at 0x...>
```

Журнал захода, писавшийся всю смену, в память целиком не влезает, но построчно читается так же просто, как список: файл сам по себе итератор, а генератор поверх него отбрасывает лишнее и отдаёт по одному разобранному событию, держа в памяти только текущую строку.

```python
def read_events(path):
    """Отдаёт события журнала по одному, не читая файл целиком."""
    with open(path) as f:
        for line in f:
            if not line.strip() or line.startswith('#'):
                continue           # пустые строки и комментарии пропускаем
            t, channel, value = line.split()
            yield float(t), channel, float(value)

for t, channel, value in read_events('run042.log'):
    if channel == 'BPM01':
        print(t, value)
```

Обратный случай — бесконечная последовательность. Генератор считает, пока спрашивают, а границу ставит читающий: `itertools.islice` берёт первые сколько-то значений и отпускает генератор.

```python
import itertools

def clock(dt):
    """Бесконечная последовательность моментов времени с шагом dt."""
    t = 0.0
    while True:
        yield t
        t += dt

for t in itertools.islice(clock(0.02), 5):
    print(round(t, 3))  # 0.0, 0.02, 0.04, 0.06, 0.08 — по одному в строке
```

Когда генератор просто пересказывает элементы другого источника, цикл с `yield` записывают короче через `yield from`. Это не только сахар: конструкция пробрасывает во вложенный генератор всё, что посылают через `send` и `throw`, а наружу отдаёт его `return`, что понадобится при вложенных генераторах.

```python
numbers = [1, 2, 3]

# Стандартный подход
def func():
    for item in numbers:
        yield item

# Упрощенный подход
def func():
    yield from numbers
```

## Корутины

Корутины выросли из генераторов и решают задачу не параллельного счёта, а ожидания: один поток занимается другим делом, пока текущая задача ждёт ответа от сети или диска.

Генератор только отдаёт значения наружу, а корутина умеет и **принимать** их. Выражение `deposit = (yield)` приостанавливает функцию и ждёт, пока снаружи вызовут `send`. Выходит диалог с функцией, сохраняющей между вопросами своё состояние.

Разберём на счёте сложных процентов. Коэффициент роста, посчитанный один раз при создании корутины, дальше не меняется, а суммы вклада в неё можно слать бесконечно.

```python
import math
from collections.abc import Generator

def cash_return_coro(percent: float,
                     years: int) -> Generator[float | None, float, None]:
    value = math.pow(1 + percent / 100, years)
    while True:
        try:
            deposit = (yield)
            yield round(deposit * value, 2)
        except GeneratorExit:
            print('Выход из корутины')
            raise

# Использование
coro = cash_return_coro(5, 5)
next(coro)
values = [1000, 2000, 5000, 10000, 100000]
for item in values:
    print(coro.send(item))
    next(coro)
coro.close()
```

За один оборот цикла корутина замирает дважды: сначала на `yield`, принимающем вклад, потом на `yield`, отдающем результат. Поэтому `send` возвращает посчитанное число, а следующий за ним `next` доводит корутину до очередного приёма.

## Что дальше

Итератор отдаёт элементы по одному, генератор приостанавливает функцию на `yield` и продолжает с места, запомненного при остановке, а корутина умеет ещё и принимать значения через `send()`.

На этом построена асинхронность в Python: цикл событий — планировщик, который переключается между приостановленными генераторами и отдаёт процессорное время тому, кто готов работать, пока остальные ждут ответа от сети или диска. Как это устроено внутри и как этим пользоваться через `asyncio`, разбирается в главе про асинхронность в разделе «Ускоряем код».
