# Объекты и память

Данная глава посвящена тому, что происходит за именем переменной, и мы разберём, чем изменяемые объекты отличаются от неизменяемых и почему это различие всплывает в самых неожиданных местах, а заодно приведём в порядок условные конструкции и циклы, написанные наспех. Многое из перечисленного здесь выглядит мелочью, пока эта мелочь не съест полдня отладки.

## Объекты в памяти

В Python **объектом является всё**: и число, и строка, и функция, и сам класс. У любого объекта есть три вещи. Тип определяет набор действий, разрешённых с объектом (`int`, `str`, `list`). Значение — это данные, лежащие внутри (`42`, `"hello"`). И наконец, идентификатор, то есть закреплённое за объектом на всё время жизни уникальное число; в CPython это адрес объекта в памяти, получаемый функцией `id()`.

```python
s = "hello"
print(id(s))  # Выведет что-то вроде 4390213040
```

### Ссылки, а не копии

Переменная в Python не «содержит» объект, а лишь ссылается на него, поэтому присваивание одной переменной другой заводит второе имя для того же объекта, а записанные данные остаются на месте. Изменив объект через одно имя, ты увидишь внесённую правку и через второе.

```python
a = [1, 2, 3]
b = a
b.append(4)
print(a)  # [1, 2, 3, 4] — изменился и a!
```

### Сравнение `is` и `==`

Из описанной картины следуют два разных вопроса, постоянно смешиваемых новичками, поскольку `is` спрашивает, **один ли это объект**, а `==` сравнивает **значения**. Два списка могут быть равны поэлементно и при этом оставаться разными объектами, лежащими в памяти по разным адресам.

```python
x = [1, 2]
y = [1, 2]
print(x == y)  # True
print(x is y)  # False
```

#### Кеширование целых чисел

При запуске интерпретатор заранее создаёт объекты для небольших целых чисел, и в CPython это диапазон от −5 до 256, из-за чего все переменные с перечисленными значениями ссылаются на один и тот же заготовленный объект.

```python
a = 256
b = 256
print(a is b)  # True — это один и тот же закешированный объект
```

Казалось бы, для 257 должно быть `False`, но проверь сам, потому что результат зависит от того, **как** ты запускаешь код.

```python
c = 257
d = 257
print(c is d)
```

Запустив это файлом, получишь `True`, а введя те же три строки в интерактивной оболочке, получишь `False`.

Причина, объясняющая разницу, не в кеше чисел, а в работе компилятора. Python компилирует файл целиком и складывает все константы блока в общую таблицу, хранящую одинаковые значения лишь однажды, поэтому `c` и `d` получают ссылку на одну и ту же записанную константу. В интерактивной оболочке каждая строка компилируется отдельно, общей таблицы нет, и создаются два разных объекта, не связанных друг с другом.

Сама история остаётся курьёзом, а вот следствие из неё серьёзное. **Тождественность объектов относится к деталям реализации, и опираться на неё нельзя.** Она зависит от версии интерпретатора, от выбранного способа запуска и даже от того, лежат ли строки в одной функции.

> 💡 **Золотое правило**: используй `==` для сравнения значений, а `is` оставь только для проверки на `None`, `True` и `False`.

## Изменяемые и неизменяемые объекты

Это главное деление, проведённое в мире объектов Python, и запомнить его придётся наизусть.

### Неизменяемые (immutable)

К неизменяемым относятся `int`, `float`, `str`, `tuple`, `bytes` и `bool`. Однажды созданный объект хранит записанное в нём значение навсегда. Любая «модификация» заводит новый объект, а старое имя переставляют на него, в чём проще всего убедиться по идентификатору, меняющемуся после каждого `+=`.

```python
s = "hello"
print(id(s))
s += "!"
print(id(s))  # ID изменился — это новый объект!
```

### Изменяемые (mutable)

`list`, `dict` и `set`, наоборот, меняются на месте. Список после `append` остаётся тем же самым объектом, у него лишь стало на один элемент больше, и все имена, ссылавшиеся на него, увидят добавленный элемент.

```python
lst = [1, 2]
print(id(lst))
lst.append(3)
print(id(lst))  # ID остался прежним
```

### Кортежи с изменяемыми элементами

Неизменяемость кортежа распространяется только на него самого, поскольку кортеж хранит ссылки, и неизменны как раз они, поэтому подставить в заполненную ячейку другой объект нельзя. А сам объект, указанный ссылкой, о запрете ничего не знает.

```python
t = ([1, 2], [3, 4])
t[0].append(3)
print(t)  # ([1, 2, 3], [3, 4]) — это допустимо!
```

Отсюда практическое ограничение, состоящее в том, что описанный кортеж нельзя положить в множество или использовать как ключ словаря, поскольку хеш кортежа складывается из хешей его элементов, а у списка хеша нет. Попытка кончится исключением `TypeError: unhashable type: 'list'`, брошенным прямо при вставке.

## Строки и байты

Два неизменяемых типа, намертво спутанных в голове новичка. Развести их надо сразу и раз навсегда.

### Строки (str)

`str` хранит текст, то есть последовательность символов Unicode. Длина строки измеряется в символах, а не в байтах, и один символ может быть каким угодно: латинской буквой, кириллической, иероглифом, значком эмодзи. Как эти символы разложены в памяти, тебя не касается: раскладкой, спрятанной от программиста, занимается интерпретатор.

### Байты (bytes)

`bytes` хранит сырые данные, то есть последовательность чисел от 0 до 255, то самое, что лежит в файле, приходит по сети или снимается с прибора, подключённого к машине. Никакого понятия «символ» здесь нет, только числа, прочитанные как есть. Тип тоже неизменяемый; изменяемый его вариант называется `bytearray`.

Между этими двумя мирами нет автоматического перехода, поскольку нужна кодировка, указывающая, каким набором байтов записан каждый символ. Отсюда пара методов, из которых `encode` превращает текст в байты, а `decode` делает обратное превращение полученных байтов в текст.

```python
text = "привет"
encoded = text.encode('utf-8')  # str -> bytes
decoded = encoded.decode('utf-8')  # bytes -> str
```

Кириллица в UTF-8 занимает по два байта на символ, поэтому `len(text)` даст 6, а `len(encoded)` вернёт 12. Почти все `UnicodeDecodeError` растут отсюда, ведь записанные байты читают не в той кодировке, в которой их сохранили.

## Условные конструкции

### Базовый синтаксис

Ветвление в Python обходится без круглых и фигурных скобок, достаточно условия, двоеточия и блока, набранного с отступом.

```python
temperature = 15
if temperature > 20:
    print("Наденьте футболку")
else:
    print("Лучше взять куртку")
```

### Элегантные проверки

В условии не обязательно писать сравнение, выписанное полностью, поскольку любой объект сам по себе истинен или ложен, а пустая строка, пустой список, ноль и `None` ложны, всё остальное истинно. Поэтому `if name:` читается как «если имя вообще есть» и заменяет громоздкое `if name != "":`

```python
name = input("Введите имя: ")
if name:  # False, если строка пустая
    print(f"Привет, {name}!")
else:
    print("Привет, незнакомец!")
```

### Современный `match` (Python 3.10+)

Когда одну переменную нужно сравнить с десятком значений, лестница из `elif` становится нечитаемой, и на описанный случай есть `match`, аналог `switch`, заимствованный из других языков. Ветви перебираются сверху вниз, вертикальная черта, объединяющая несколько вариантов в один случай, экономит строки, а `case _` ловит всё, не пойманное раньше.

```python
http_status = 404
match http_status:
    case 200 | 201:
        print("Успех")
    case 401 | 403 | 404:
        print("Ошибка клиента")
    case 500 | 503:
        print("Ошибка сервера")
    case _:
        print("Неизвестный статус")
```

> 💡 **Совет**: бери `match`, когда сравниваешь одну переменную с несколькими значениями. Для сложных условий оставайся с `if/elif/else`.

## Циклы

### `while`

`while` повторяет тело, пока условие истинно, и нужен там, где число итераций заранее неизвестно, например пока значение не выйдет за заданную границу.

```python
i = 1
while i < 1000:
    print(i)
    i *= 2
```

### `for` и `range`

`for` в Python перебирает не индексы, а элементы, поставляемые ему `range`, если нужен привычный счётчик. С одним аргументом он отсчитывает от нуля, с тремя задаёт начало, границу и шаг. Правая граница, указанная в `range`, в диапазон не входит.

```python
for i in range(5):      # 0, 1, 2, 3, 4
    print(i)

for i in range(1, 10, 2):  # 1, 3, 5, 7, 9
    print(i)
```

### `enumerate` для получения индекса

Когда вместе с элементом нужен и его номер, заводить отдельную переменную-счётчик, увеличенную вручную, не надо, поскольку `enumerate` выдаёт пары «индекс, элемент», распаковываемые прямо в заголовке цикла.

```python
for idx, char in enumerate("abc"):
    print(f"Индекс: {idx}, Символ: {char}")
```

### Ветка `else` в циклах

У циклов в Python есть ветка `else`, не встречающаяся почти нигде больше. Она выполняется, если цикл завершился **естественно**, то есть перебрал всё до конца и ни разу не наткнулся на `break`. Получается готовый каркас для поиска, собранный из двух веток: в теле цикла ищешь и выходишь по `break`, а в `else` пишешь ветку «не нашли».

```python
for i in range(5):
    if i == 10:
        break
else:
    print("Цикл завершился без break")
```

## Производительность при работе со строками

Теперь вернёмся к неизменяемости строк, объявленной выше, и посмотрим, во что она обходится на практике.

Каждое `+=` для строки создаёт новый объект и копирует в него всё накопленное раньше. На сотой итерации копируется сто символов, на стотысячной сто тысяч, и в сумме набегает квадратичное время вместо линейного, обещанного простым циклом.

```python
result = ""
for _ in range(100000):
    result += "a"  # Создаёт новый объект на каждой итерации!
```

Оговорка, впрочем, нужна. Если на строку не смотрит никто, кроме локальной переменной, интерпретатор дописывает её на месте, и в теле функции этот же цикл идёт за линейное время, тогда как на уровне модуля, где на строку смотрит ещё и словарь глобальных имён, время растёт квадратично. Оптимизация держится на счётчике ссылок, пропадает от любого лишнего имени и языком не гарантирована. Учти это, когда будешь проверять замер через `timeit`: он оборачивает код в функцию, и квадратичного роста ты там не увидишь.

Правильнее копить куски в списке, растущем на месте, и склеить их один раз. Список изменяем, `append` ничего не копирует, а `join` заранее считает итоговую длину, выделяет память один раз и переносит туда все собранные части.

```python
parts = []
for _ in range(100000):
    parts.append("a")
result = "".join(parts)  # Быстрое объединение
```

> 💡 **Совет**: для частых операций конкатенации используй `list` + `join()` для строк или `bytearray` для байтов.

## Сборка мусора

Память, выделенная под объекты, в Python освобождается сама, и делают это два механизма.

Основным считается **подсчёт ссылок**, при котором у каждого объекта есть счётчик, показывающий, сколько имён и контейнеров на него смотрят. Как только счётчик падает до нуля, объект уничтожается немедленно. Быстро, предсказуемо, и в большинстве программ ничего сверх этого не нужно.

У подсчёта ссылок есть слепое пятно, называемое циклическими ссылками. Если объекты ссылаются друг на друга, их счётчики никогда не обнулятся, даже когда до потерянной пары уже нельзя добраться из программы.

```python
a = []
b = [a]
a.append(b)  # Теперь a и b ссылаются друг на друга
del a, b     # Объекты недостижимы, но ссылки остались
```

Для таких случаев есть второй механизм, **поколенческий сборщик мусора**. Он запускается периодически, находит «острова» из объектов, ссылающихся друг на друга, до которых больше не дотянуться, и удаляет их целиком. Поколенческий он потому, что молодые объекты проверяет часто, а пережившие несколько проверок — редко, так как статистика говорит, что долгоживущий объект скорее всего проживёт ещё.

## Неочевидные особенности Python

### 1. Изменяемые аргументы по умолчанию

Самая известная ловушка языка, выросшая прямо из деления объектов на изменяемые и неизменяемые. Значение по умолчанию, записанное в заголовке, считается **один раз**, когда интерпретатор доходит до строчки `def`, после чего список живёт между вызовами и копит всё положенное в него.

```python
def append_to(element, target=[]):  # так делать нельзя!
    target.append(element)
    return target

print(append_to(1))  # [1]
print(append_to(2))  # [1, 2] — тот же список!
```

Лекарство одно, названное в любом руководстве: по умолчанию ставят `None`, а настоящий пустой список, создаваемый заново на каждом вызове, заводят уже внутри функции.

```python
def append_to(element, target=None):
    if target is None:
        target = []
    target.append(element)
    return target
```

### 2. Ленивые логические операторы

`and` и `or` вычисляют правую часть только тогда, когда без неё не обойтись. Если левый операнд `and` ложен, результат уже известен, и правая часть, отброшенная целиком, не вычисляется вовсе. Отсюда идиома «сначала проверь, потом лезь», благодаря которой строчка `if xs and xs[0] > 0` не упадёт на пустом списке.

```python
def expensive_call():
    print("Вызов выполнен!")
    return True

# expensive_call() не будет вызвана, т.к. первое условие False
if False and expensive_call():
    pass
```

### 3. Атрибуты функций

Раз всё в Python является объектом, то и функция тоже объект, готовый принять произвольный атрибут, приписанный руками. Выглядит как забава, а на этом держатся декораторы, считающие вызовы или кеширующие результат прямо на себе.

```python
def my_func():
    pass

my_func.custom_attr = 42
print(my_func.custom_attr)  # 42
```

## Заключение

Вся глава держится на одной фразе, гласящей: переменная — это имя, привязанное к объекту, а не коробка со значением. Отсюда и общий список, полученный после двух присваиваний, и накопительный аргумент по умолчанию, и квадратичное время, потраченное на сборку строки через `+=`.

Четыре правила, выведенные отсюда, придётся выучить наизусть:

- `is` применяй только для `None`, `True` и `False`; во всех остальных случаях `==`.
- Строки собирай через `join`, а не через `+=` в цикле.
- Значение, поставленное по умолчанию, не должно быть изменяемым объектом, ставь `None`.
- Прежде чем передать объект в чужую функцию, спроси себя, изменяем он или нет.
