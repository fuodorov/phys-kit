# Функции

Функция служит первым инструментом борьбы со сложностью: кусок логики, спрятанный за именем, дальше можно не держать в голове. Синтаксис `def` ты наверняка уже знаешь, поэтому здесь мы пойдём глубже.

Разберём, как Python обходится с аргументами, а умеет он заметно больше, чем «передать по порядку», где живут переменные и по какому правилу интерпретатор их ищет, чем распаковка отличается от обычного присваивания и какие ловушки спрятаны в значениях, заданных по умолчанию.

## Синтаксис объявления функций

### Базовый синтаксис

Имя функции в Python может содержать буквы, цифры и символ подчёркивания `_`, но не может начинаться с цифры.

```python
def foo():
    return 42

foo()  # возвращает 42
```

Оператор `return` не обязателен, и функция, обходящаяся без него, возвращает `None`.

```python
def foo():
    42

print(foo())  # выводит None
```

### Документирование функций

Для документирования используются строковые литералы (docstring), стоящие первыми в теле функции.

```python
def foo():
    """I return 42."""
    return 42
```

Документация доступна через атрибут `__doc__` или функцию `help()`.

```python
print(foo.__doc__)  # 'I return 42.'
help(foo)           # показывает документацию
```

## Работа с аргументами

### Позиционные и именованные аргументы

Аргументы можно передавать двумя способами, свободно смешиваемыми в одном вызове. Позиционные разбираются по порядку, именованные по имени параметра, поэтому для них порядок, выбранный при записи, роли не играет.

```python
def min(x, y):
    return x if x < y else y

min(-5, 12)        # -5
min(x=-5, y=12)    # -5
min(y=12, x=-5)    # -5 (порядок не важен)
```

Правило одно: позиционные аргументы идут первыми. Написать `min(x=-5, 12)` не получится, поскольку интерпретатор не поймёт, к какому параметру относится `12`, которое осталось без имени.

### Упаковка позиционных аргументов

Для работы с произвольным количеством аргументов используется `*args`, и звёздочка, поставленная перед именем параметра, означает «собери все лишние позиционные аргументы в кортеж и передай его под этим именем».

```python
def min(*args):
    res = float("inf")
    for arg in args:
        if arg < res:
            res = arg
    return res

min(-5, 12, 13)  # -5
min()            # inf
```

Посмотри на вызов без аргументов: `args` оказывается пустым кортежем, цикл не выполняется ни разу, и функция возвращает начальное значение, хотя минимума у пустого набора нет и быть не может. Чтобы гарантировать хотя бы один аргумент, его выносят в отдельный обязательный параметр, который стоит перед `*args`.

```python
def min(first, *args):
    res = first
    for arg in args:
        if arg < res:
            res = arg
    return res

min()  # TypeError: min() missing 1 required positional argument: 'first'
```

### Распаковка аргументов

Звёздочка работает и в обратную сторону, разбирая в месте вызова готовую последовательность на отдельные аргументы. Годится любой итерируемый объект, поданный туда, будь то список, кортеж, множество или генератор.

```python
xs = {-5, 12, 13}
min(*xs)           # -5
min(*[-5, 12, 13]) # -5
min(*(-5, 12, 13)) # -5
```

### Ключевые аргументы и значения по умолчанию

Всё, что записано в объявлении **после** `*args`, можно передать только по имени, поскольку позиции для этих параметров уже кончились. Так делают необязательные настройки. У них есть разумное значение по умолчанию, а если вызывающий его меняет, то делает это явно и читаемо.

```python
def bounded_min(first, *args, lo=float("-inf"), hi=float("inf")):
    res = hi
    for arg in (first,) + args:
        if arg < res and lo < arg < hi:
            res = arg
    return max(res, lo)

bounded_min(-5, 12, 13, lo=0, hi=255)  # 12
```

Из трёх чисел в границы `[0, 255]` попадают 12 и 13, минимальное из них равно 12; значение −5 отброшено как выходящее за нижнюю границу, которую задаёт параметр `lo`.

### Опасность изменяемых значений по умолчанию

Значение по умолчанию вычисляется один раз, в момент, когда интерпретатор читает строку `def`, а не при каждом вызове, приходящем потом. Для числа или строки это незаметно, но изменяемый объект, созданный однажды, окажется общим для всех вызовов и станет копить состояние, переползающее из вызова в вызов.

```python
def unique(iterable, seen=set()):
    acc = []
    for item in iterable:
        if item not in seen:
            seen.add(item)
            acc.append(item)
    return acc

xs = [1, 1, 2, 3]
unique(xs)  # [1, 2, 3]
unique(xs)  # [] 😱
```

Второй вызов на тех же данных возвращает пустой список, поскольку множество `seen` уже содержит все числа, которые попали туда в прошлый раз. Лечение мы уже видели: в объявлении ставят `None`, а настоящее пустое множество создают внутри функции, заново на каждом вызове.

```python
def unique(iterable, seen=None):
    seen = set(seen or [])  # None - falsy значение
    acc = []
    for item in iterable:
        if item not in seen:
            seen.add(item)
            acc.append(item)
    return acc

xs = [1, 1, 2, 3]
unique(xs)  # [1, 2, 3]
unique(xs)  # [1, 2, 3] ✅
```

### Только ключевые аргументы

Можно требовать, чтобы некоторые аргументы передавались только по имени.

```python
def flatten(xs, *, depth=None):
    pass

flatten([1, [2], 3], depth=1)  # ✅
flatten([1, [2], 3], 1)        # TypeError
```

### Упаковка ключевых аргументов

Две звёздочки делают с именованными аргументами то же, что одна с позиционными, собирая в словарь всё, что не опознано по именам. Точно так же они работают и в вызове, раскладывая словарь по именам параметров, поэтому набор настроек, живущий отдельно, удобно передавать целиком.

```python
def runner(cmd, **kwargs):
    if kwargs.get("verbose", True):
        print("Logging enabled")

runner("mysqld", limit=42)                    # ✅
runner("mysqld", **{"verbose": False})        # ✅
options = {"verbose": False}
runner("mysqld", **options)                   # ✅
```

## Распаковка и присваивание

### Базовая распаковка

Распаковка не привязана к функциям, потому что работает в любом присваивании. Слева пишут структуру, набранную из имён, справа ставят итерируемый объект, и Python раскладывает второе по первому, причём форма слева может повторять вложенность, которая есть справа.

```python
x, y, z = [1, 2, 3]           # ✅
x, y, z = {1, 2, 3}           # ✅ (но порядок не гарантирован!)
x, y, z = "xyz"               # ✅

# Распаковка вложенных структур
rectangle = (0, 0), (4, 4)
(x1, y1), (x2, y2) = rectangle
```

Случай с множеством отметь особо: код отработает, но число, попавшее в `x`, не определено, потому что порядка у множества нет. Так писать нельзя.

### Расширенная распаковка (Python 3.0+)

Звёздочка слева от знака равенства собирает «всё остальное» в список. Имя, помеченное ею, может стоять в любом месте, в начале, в конце или в середине; Python сначала раздаёт значения обычным именам, а остаток, не разобранный ими, достаётся звёздочке.

```python
first, *rest = range(1, 5)           # first=1, rest=[2, 3, 4]
first, *rest, last = range(1, 5)     # first=1, rest=[2, 3], last=4

# Можно использовать в любом месте
*_, (first, *rest) = [range(1, 5)] * 5
```

Имя со звёздочкой может получить и пустой список, а вот обычные имена должны получить по значению. Если значений не хватает даже на них, будет ошибка.

```python
first, *rest, last = [42]  # ValueError
```

### Распаковка в цикле for

Заголовок цикла — тоже присваивание, поэтому распаковка работает и там. Элементы, идущие подряд, могут быть разной длины, и обычные имена возьмут своё, а звёздочка подберёт остаток.

```python
for a, *b in [range(4), range(2)]:
    print(b)
# Вывод:
# [1, 2, 3]
# [1]
```

## Области видимости (Scopes)

### Функции внутри функций

Функции в Python относятся к объектам первого класса, а потому их определяют внутри других функций, передают в аргументах, возвращают как результат. Ничего особенного в `def`, вложенном в `def`, нет — это обычное присваивание, просто локальное.

```python
def wrapper():
    def identity(x):
        return x
    return identity

f = wrapper()
f(42)  # 42
```

### Правило LEGB

Раз области видимости вкладываются друг в друга, нужно правило, решающее, какая из них победит. Интерпретатор ищет имя в четырёх областях по порядку и останавливается на первой найденной:

- **L**ocal (локальная), имена, объявленные внутри самой функции.
- **E**nclosing (объемлющая), имена объемлющей функции, если эта вложена в другую.
- **G**lobal (глобальная), имена уровня модуля.
- **B**uilt-in (встроенная), имена, доступные всегда, например `len`, `print` и `min`.

```python
min = 42  # global

def f(*args):
    min = 2  # enclosing
    def g():
        min = 4  # local
        print(min)
```

Здесь три разных `min`, и они не конфликтуют, так как `g` печатает свой, локальный. Убери из `g` строку с присваиванием, и печататься начнёт `min`, объявленный в `f`; убери её и оттуда, тогда доберёмся до глобальной 42. Заодно видно, почему переменные не называют именами встроенных функций: последнее звено цепочки, встроенный `min`, оказывается закрытым.

### Замыкания и позднее связывание

Имя, которое функция не определяет сама, разрешается не при объявлении, а **в момент вызова**. Поведение, устроенное так, называется поздним связыванием, и отсюда прямое следствие. `f` ниже вообще не знает, откуда возьмётся `i`, а просто на каждом вызове смотрит на значение, лежащее под этим именем сейчас.

```python
def f():
    print(i)

for i in range(4):
    f()
# Вывод:
# 0
# 1
# 2
# 3
```

Здесь никакого замыкания ещё нет, ведь `i` остаётся обычным глобальным именем. **Замыкание** возникает, когда вложенная функция пользуется именем, взятым из объемлющей, и продолжает пользоваться им даже после того, как та завершилась.

```python
def make_adder(step):
    def add(x):
        return x + step      # step взят из объемлющей функции
    return add

add5 = make_adder(5)
print(add5(10))                          # 15
print(add5.__closure__[0].cell_contents) # 5 — значение живёт в замыкании
```

Функция `make_adder` давно вернулась, её локальные переменные должны были исчезнуть, но `step` жив благодаря `add`, ссылающейся на него. На механизме, разобранном здесь, и построены декораторы из следующей главы.

Позднее связывание и замыкания вместе дают классическую ловушку. Функции, созданные в цикле, захватывают **переменную**, а не значение, записанное в ней, и после цикла все разом видят последнее.

```python
funcs = [lambda: i for i in range(3)]
print([f() for f in funcs])          # [2, 2, 2], а не [0, 1, 2]

funcs = [lambda i=i: i for i in range(3)]
print([f() for f in funcs])          # [0, 1, 2]
```

Во второй строке значение фиксируется аргументом по умолчанию, вычисляемым, в отличие от тела функции, сразу при её создании.

### Присваивание и области видимости

Есть важная асимметрия: читать имя можно из любой внешней области, а присваивание всегда создаёт **локальную** переменную. Причём решение, принятое при компиляции функции, распространяется на всё её тело, поэтому `min += 1` падает не на присваивании, а на попытке прочитать локальную `min`, ещё не получившую значения.

```python
min = 42

def f():
    min += 1  # UnboundLocalError!
    return min
```

### Оператор global

Чтобы менять глобальную переменную, а не заводить одноимённую локальную, о намерении надо заявить явно.

```python
min = 42

def f():
    global min
    min += 1
    return min

f()  # 43
f()  # 44
```

Заявлять приходится нарочно и многословно, и это сделано специально. Функция, правящая глобальное состояние, перестаёт быть предсказуемой, и результат, возвращённый ею, зависит от числа предыдущих вызовов. Пользуйся `global` только там, где без него никак.

### Оператор nonlocal (Python 3+)

`nonlocal` делает то же самое, но для объемлющей функции, а не для модуля. Это единственный способ дать вложенной функции менять переменную той, в которую она вложена, и на нём держатся счётчики и накопители, спрятанные внутри декораторов.

```python
def cell(value=None):
    def get():
        return value
    def set(update):
        nonlocal value
        value = update
    return get, set

get, set = cell()
set(42)
get()  # 42
```

Получилась ячейка памяти, в которой две функции разделяют одну переменную `value`, живущую ровно столько же, сколько они сами. Снаружи до неё не добраться никак, только через `get` и `set`. Получается объект с приватным полем, собранный из одних функций.

## Функциональное программирование

### Анонимные функции (lambda)

Иногда функция нужна на одну строчку, чтобы передать в `sorted` или в `map`, и придумывать ей имя незачем. Для таких случаев есть `lambda`, задающая функцию выражением. Тело у неё всегда одно выражение, и значение, посчитанное им, становится результатом, без всякого `return`.

```python
lambda arguments: expression

# Эквивалентно:
def <lambda>(arguments):
    return expression
```

Список параметров у лямбды такой же богатый, как у обычной функции, со звёздочками и значениями, проставленными по умолчанию.

```python
lambda x: x ** 2
lambda foo, *args, bar=None, **kwargs: 42
```

Ограничение в одно выражение поставлено намеренно. Как только логика перестаёт помещаться в строку, перед тобой самостоятельный кусок программы, а не деталь вызова, и пора дать ему имя через `def`. По этой же причине PEP 8 запрещает присваивать лямбду переменной. Запись `f = lambda x: ...` ничем не лучше `def f(x): ...`, зато теряет имя в трассировке, напечатанной при ошибке.

### Функции map, filter, zip

Три встроенные функции покрывают три самые частые операции, выполняемые над последовательностью: преобразование каждого элемента, отбор нужных и одновременный проход по нескольким наборам. Все три ничего не вычисляют сразу, а возвращают ленивый объект, поэтому в примерах результат обёрнут в `list`.

`map` применяет функцию к каждому элементу, приходящему из источника.

```python
list(map(lambda x: x % 7, [1, 9, 16, -1, 2, 5]))  # [1, 2, 2, 6, 2, 5]
```

`filter` оставляет только элементы, для которых функция вернула истину, и есть у него особый режим. Если вместо функции передать `None`, фильтр отсеет всё, ложное само по себе: нули, пустые коллекции и пустые строки.

```python
list(filter(lambda x: x % 2 != 0, range(10)))  # [1, 3, 5, 7, 9]

# С None - оставляет только truthy значения
xs = [0, None, [], {}, set(), "", 42]
list(filter(None, xs))  # [42]
```

`zip` идёт по нескольким последовательностям параллельно и на каждом шаге отдаёт кортеж, собранный из их элементов. Останавливается он по самой короткой, и лишние элементы длинных последовательностей просто теряются. Об этом забывают постоянно.

```python
list(zip("abc", range(3), [42j, 42j, 42j]))
# [('a', 0, 42j), ('b', 1, 42j), ('c', 2, 42j)]
```

### Включения коллекций

Всё то же самое можно записать выразительнее, через включения. Форма, приведённая ниже, читается как фраза «взять `x ** 2` для каждого `x` из `range(10)`, если `x` нечётно». Второй пример показывает ту же операцию, записанную через `map` и `filter`, и стоит сравнить, насколько он тяжелее для глаза. А два `for`, поставленные подряд, разворачивают вложенную структуру в плоский список; порядок их такой же, как во вложенных циклах.

```python
[x ** 2 for x in range(10) if x % 2 == 1]  # [1, 9, 25, 49, 81]

# Эквивалент с map/filter:
list(map(lambda x: x ** 2, filter(lambda x: x % 2 == 1, range(10))))

# Вложенные включения:
nested = [range(5), range(8, 10)]
[x for xs in nested for x in xs]  # [0, 1, 2, 3, 4, 8, 9]
```

Тот же синтаксис работает для множеств и словарей, только скобки другие. Фигурные скобки с одним выражением дают множество, и в первом примере остатки, совпавшие между собой, схлопнулись; а с парой, разделённой двоеточием, получается словарь.

```python
{x % 7 for x in [1, 9, 16, -1, 2, 5]}  # {1, 2, 5, 6}

date = {'year': 2014, "month": "September", "day": ""}
{k: v for k, v in date.items() if v}  # {'year': 2014, 'month': 'September'}

{x: x ** 2 for x in range(4)}  # {0: 0, 1: 1, 2: 4, 3: 9}
```

Во втором примере условие `if v` отбрасывает записи с пустым значением, и работает здесь та же истинность объектов, применяемая и в `filter(None, ...)`.

## PEP 8 и стиль кода

Код читают чаще, чем пишут, и общий стиль экономит время всем. PEP 8 представляет собой официальное соглашение о том, как выглядит питоновский код, написанный по правилам; его понимает любой линтер, и спорить о скобках после него не приходится.

### Базовые рекомендации

- 4 пробела для отступов, задающих структуру блока
- Максимум 79 символов в строке кода
- `lower_case_with_underscores` для переменных и функций
- `UPPER_CASE_WITH_UNDERSCORES` для констант

### Выражения и операторы

Правила, собранные ниже, не вкусовщина, у каждого есть причина. Пробелы вокруг операторов расставляют по приоритету, чтобы структура выражения была видна глазом. Тело `if` всегда переносят на новую строку, потому что однострочник тяжелее заметить при беглом чтении, да и точку останова на нём не поставишь. Сравнение пишут в естественном порядке, ставя проверяемую переменную слева от значения, а отрицание принадлежности записывают оператором `not in`, а не через `not ... in`.

```python
exp = -1.05
value = (item_value / item_count) * offset / exp
hypot2 = x*x + y*y

if bar:
    x += 1

if method == 'md5':
    pass

if key not in d:
    pass
```

Ниже приведены те же четыре конструкции, записанные так, как делать не стоит.

```python
value = ( item_value/item_count )*offset/exp

if bar: x += 1

if 'md5' == method:
    pass

if not key in d:
    pass
```

### Функции

Отдельное соглашение есть про строки документации. Первая строка содержит короткое описание, уложенное в одно предложение, потом идёт пустая строка, потом при необходимости подробности. Кавычки тройные даже у однострочника. Если описание разрастётся, менять их не придётся.

```python
def something_useful(arg, **options):
    """One-line summary.

    Optional longer description.
    """
    pass
```

## Резюме

- Функции принимают произвольное количество позиционных (`*args`) и ключевых (`**kwargs`) аргументов
- Синтаксис распаковки работает в вызовах функций, присваивании и циклах
- Имена ищутся по правилу LEGB: локальная, объемлющая, глобальная, встроенная область
- Присваивание создаёт локальную переменную; поведение, заданное по умолчанию, меняют через `global` и `nonlocal`
- Значение по умолчанию вычисляется один раз, поэтому изменяемым оно быть не должно
- Python поддерживает элементы функционального программирования: lambda, map, filter, zip, включения коллекций
- PEP 8 описывает, как должен выглядеть читаемый код, и правила, записанные в нём, проверяют линтеры
