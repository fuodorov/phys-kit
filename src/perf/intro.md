# С чего начинать оптимизацию

Python прекрасен всем, кроме скорости. Интерпретация, динамическая типизация, объектная модель — всё, делающее язык удобным, стоит дорого. Наивный цикл на Python работает в десятки и сотни раз медленнее того же кода на C. Для скрипта, запускаемого раз в день, это неважно, а для обработки терабайта данных с детектора или моделирования миллиона частиц разница — часы против недель.

Медленный Python почти всегда можно ускорить, не переписывая всё на C++. В этом разделе по порядку:

- [Почему Python не очень быстрый](../dev/python/optimization.md) рассказывает, откуда берётся разница с C, и вводит инструменты, позволяющие измерить время: `cProfile`, `line_profiler`, `py-spy`, `timeit`;
- [Что выжать из самого Python](./python-tricks.md) собирает приёмы, не требующие ничего, кроме языка: выбор структуры, встроенные функции, экономия памяти;
- [Скорость выполнения программ](./perf.md) разгоняет один и тот же расчёт по очереди: сперва Numba, потом Cython и в конце NumPy;
- [Многопоточность и GIL](./gil.md) объясняет, почему потоки в Python не ускоряют вычисления, что такое глобальная блокировка интерпретатора и когда спасают порождённые процессы;
- [Асинхронность](./async.md) разбирает цикл событий и `asyncio`, опираясь на корутины из главы «Итераторы, генераторы и корутины», и показывает, как ждать тысячи одновременно запущенных операций ввода-вывода;
- [CUDA и вычисления на GPU](./cuda.md) показывает, когда и как перенести расчёт на видеокарту с помощью CuPy и Numba.

**Не оптимизируй вслепую.** Интуиция почти всегда врёт о том, где программа проводит время; время показывает только профилировщик.
