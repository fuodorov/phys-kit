# Ревью чужого кода

> Опирается на главы [«Жизненный цикл ПО»](../dev/life.md) и [«Требования к коду»](../dev/python/requirements.md).



## Что нужно сделать

- Провести ревью предложенного кода, отыскав в нём ошибки, неточности и неэффективные места и дав рекомендации по улучшению.
- Задача не сводится к исправлению ошибок: нужны комментарии и рекомендации.

## Что сдавать

- Ссылка на форк, где замечания стоят **комментариями к строкам кода**. Проще всего так: завести в своём форке ветку с исправлениями и открыть pull request внутри форка, из этой ветки в `main`; в диффе GitHub даёт комментировать каждую строку. Отдельный текстовый файл со списком замечаний не подходит: замечание должно стоять рядом с кодом.
- Замечания разделены на два вида: **ошибки**, из-за которых программа работает неверно или падает, и **рекомендации**, где код работает, но написан неудачно.
- У каждой ошибки указано, при каких данных она проявится. «Тут может упасть» замечанием не считается.
- У каждой рекомендации указано, что она улучшает: скорость, читаемость или устойчивость к изменениям.
